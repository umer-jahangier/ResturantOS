# 38-15 — Accessibility

## Goal

Target WCAG 2.2 AA where practical, starting with the defect every keyboard user pays on every
page load.

## Why

Phase 20 did the hard part — the contrast work is measured and green (53 pairings, plus 34-02's 20
glass rows, binding constraint 5.34:1), the focus indicator is a real `outline` and survives
Windows High Contrast where the previous `ring` was **absent entirely**, and status is never
carried by hue alone (the KDS's four redundant channels are the model). None of that is reopened.

What the audit measured:

| | measured | contract |
|---|---|---|
| **Skip links** | **0** on every route | 1, first focusable |
| **Tab presses to reach `<main>`** | **22** — stops 1–21 are the branch switcher and sidebar links; #22 lands on a tab strip | **≤ 2** |
| `<h1>` per page | **0** on `/app/pos`, `/app/pos/tills`, POS order management, `/app/hr/attendance` | exactly 1 |
| Sub-44px interactive targets | **108** on `/app/purchasing/purchase-orders`; 63 vendors; 62 ingredients; 31 hr-attendance; 30 stock | 0 on operational; 44px hit area elsewhere |
| Unlabelled inputs | **6** on `/app/hr/attendance` (3 selects, a date, 2 more) + **3** unnamed controls | 0 |
| Required-field marking | **0** in both audited dialogs | every required field |
| `aria-modal` | **unset** on all three dialogs probed, palette included | set |
| Focus outline | `2px solid` on every stop ✓ | keep |
| Focus scrolled into view | `inView: true` ✓ | keep |
| Colour-only status | not found ✓ | keep |

**The 22-Tab figure is the one to act on.** It is paid on every page load, by every keyboard user,
on all 65 routes. It is also why the command palette (38-11) matters — phase 20 called it the
escape hatch, and it currently finds nothing.

## Tasks

1. **Skip link.** `Skip to content` as the first focusable element on every page, visually hidden
   until focused, targeting `<main>`. Delivered through `PageBody`/the shell so it cannot be
   forgotten per route.

2. **Landmarks.** One `<main>`, one `<nav>` per navigation region with an accessible name, `<h1>`
   owned by `PageHeader` — closing the four zero-`h1` screens.

3. **Target sizes.** 44 × 44px on every operational control; back-office table rows may render at
   32px with a **44px hit area** via padding, which satisfies SC 2.5.8 without inflating a dense
   grid.

4. **Labelling.** Every input has an accessible name. `/app/hr/attendance`'s six unlabelled inputs
   and three unnamed controls — **re-audit in a browser against a running `hr-service` first**;
   these are source-derived findings.

5. **Required marking** — visual plus `aria-required` (shared with 38-03).

6. **`aria-modal="true"`** on every dialog surface.

7. **Accessible form errors** (§22): `aria-invalid`, `aria-describedby` pointing at the message,
   and focus moved to the first invalid field on submit.

8. **Live regions.** `status-announcer.tsx` exists — verify every async result (save, delete,
   filter change, row count change) announces once, and only once.

9. **Gate G12**, extended to all of the above, run across every reachable route.

| Check | Kind | Passes when |
|---|---|---|
| **Skip link** | e2e | present, first in tab order, visible on focus, moves focus into `<main>` on every route |
| **Tabs to main** | e2e | **≤ 2** on every route. **Baseline 22** |
| `<h1>` | e2e | exactly 1 per route, all 65 |
| Landmarks | e2e | one `<main>`; every `<nav>` named |
| Target size | e2e | 0 controls < 44×44 hit area. Baselines: 108 / 63 / 62 / 31 / 30 → 0 |
| Labels | e2e | 0 inputs without an accessible name |
| Required | unit | visual marker + `aria-required` |
| `aria-modal` | e2e | set on every dialog |
| Form errors | e2e | `aria-invalid` + `aria-describedby`; focus lands on the first invalid field |
| Announcements | e2e | one announcement per async result, not two |
| Contrast | unit | phase 20's 53 + 34-02's 20 still green, unmodified |
| Reduced motion | e2e | both directions (38-13) |

### Negative controls — observe each failing

1. Delete the skip link → skip check red **and** tabs-to-main red (should return to ~22).
2. Add a second `<h1>` → `h1` red.
3. Shrink a row action to a 32px hit area → target red.
4. Remove a label from an attendance input → label red.
5. Announce a save twice → announcement red.
6. Move a token to break one pairing → contrast red on **that pairing**, naming it.

> **Do not anchor the label or target gates on HR routes while `hr-service` is down.** They will
> *skip* and report green — pattern #4 from `SURFACE-MOTION-SPEC.md` §7, where the positive control
> was anchored to a dashboard that errors whenever a backing service is unavailable. Anchor on
> `/app/purchasing/purchase-orders` and `/app/inventory/stock`, both reachable throughout the
> audit, and assert the anchor element is attached before measuring.

## Out of scope

A full manual screen-reader pass across 65 routes — sampled, not exhaustive, and said so. WCAG AAA
beyond what phase 20 already achieved on POS/KDS text. Automated axe scanning is a supplement
here, not the gate: it does not catch a 22-Tab journey or an occluded control.
