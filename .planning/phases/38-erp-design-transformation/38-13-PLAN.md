# 38-13 — Micro-interactions and selective depth

## Goal

Spend the motion and depth vocabulary that phase 34 built, on the surfaces that earn it, and
nowhere else.

## Why this plan adds no new motion value

34-03 and 34-04 delivered a complete vocabulary and **nothing consumes most of it**. 34-03's own
summary records the gap: *"No surface has adopted `.vdl-enter` / `.vdl-stagger` yet — 34-04 and
34-06 do that. Until then the vocabulary is proven correct but not proven tasteful."* 34-04
records the same for tilt: *"No screen consumes tilt yet — 34-06 is the first."* 34-06 then
adopted glass, lift and stagger on the dashboard portlets **only**.

So the assets exist, measured, unused:

| Asset | Delivered | Adopted by |
|---|---|---|
| `.vdl-enter` / `.vdl-enter-scale` | 34-03 | login (34-07) |
| `.vdl-stagger` | 34-03 | dashboard portlet rows (34-06) |
| `.vdl-lift` | 34-03 | dashboard portlets (34-06) |
| `.vdl-reveal` | 34-03 | **nothing** |
| `.vdl-tilt` / `usePointerTilt` | 34-03/04 | **nothing** |
| `GlassPanel` | 34-04 | login (34-07) |
| `Reveal` / `RevealGroup` | 34-04 | **nothing** |
| Card depth + interactive variants | 34-04 | **nothing** — depth is opt-in per call site, deliberately |

**D-38-01: this plan introduces no new duration, easing, class or depth level.** If a surface
wants something the vocabulary lacks, the surface is wrong.

## Tasks

1. **Adopt, per zone, per the UI-SPEC §5 table:**
   - `expressive` (dashboards, reports, settings, platform console): `GlassPanel`, depth 2/3,
     `.vdl-lift` on drillable cards, `.vdl-stagger` on grids, `.vdl-reveal` on chart draw-in,
     `usePointerTilt` on KPI and product cards where a pointer exists.
   - `restrained` (lists, forms, CRUD): elevation, hover surface change, `--motion-hover` 140ms,
     `--motion-state` 120ms. **No entrance, no stagger, no tilt, no glass.**
   - `operational` (POS, KDS): press feedback at `--motion-state` and depth cues. **Nothing else.**

2. **The button and hover system** (§34, §35): hover → elevation or brightness; press → subtle
   scale; release → return. Rows → surface change. Icons → small scale. Nav → active indicator.
   All at existing tokens. **Never make hover the only way to understand functionality** — every
   hover affordance has a visible or focus-reachable equivalent.

3. **`Card` depth stays opt-in.** 34-04 asserted `Card`'s default rendering class by class
   precisely because *"Card is consumed product-wide, and a silent restyle of every card is a
   screen rebuild wearing a design pass's clothes."* Keep that assertion green.

4. **Delete the orphaned page-transition island.** `components/shared/page-transition.tsx` and
   `page-transition-motion.tsx` are referenced by nothing since 34-03 unwired them. 34-03 left
   them on disk deliberately (*"leaving them WIRED was the actual defect"*); removal is this
   plan's follow-up. **`framer-motion` stays in `package.json`** — `dependency-budget.test.ts`
   fails if it is removed without updating the baseline in the same commit, deliberately.

5. **No page transitions** (§33). §3.12 already settled this with arithmetic: an operator
   navigates ~200 times a shift and pays the duration every time.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| **Zone containment** | unit + e2e | G5: no glass, entrance, stagger or tilt resolves on a `restrained` or `operational` surface |
| **Resting-state contract** | unit | no animation class sets zero opacity, hidden visibility or a non-identity transform as a resting declaration. A `var()`-driven identity transform is permitted; a literal offset is not |
| **Reduced motion, both directions** | e2e | under the preference: decorative motion **absent** and elements **visible**. Without it: the entrance **demonstrably runs** (`vdlEnter @ 0.42s`) |
| Ceiling | unit | no duration > 240 ms outside `expressive` |
| Tilt exclusions | unit | coarse pointer **or** reduced motion **or** explicitly disabled → no tilt. Three overlapping exclusions, asserted separately |
| Tilt cost | unit | 1 `getBoundingClientRect` per gesture across a 50-move burst; ≤ 2 `setProperty` per frame across a 100-move burst — **asserted by counting calls**, never by reading source |
| `Card` default unchanged | unit | 34-04's class-by-class assertion still green |
| Page transition gone | unit | the orphaned island is referenced by nothing and the files are removed |
| Hover is never sole | e2e | every hover-revealed action is reachable by keyboard and visible on touch |

### Negative controls — observe each failing

1. Add `backdrop-blur` to a shared `Card` → G5 red on the POS. **The realistic failure mode is not
   glass on the POS; it is glass on something the POS imports.**
2. Write a keyframe as `.thing { opacity: 0 }` + `@keyframes { to { opacity: 1 } }` → resting-state
   red. That form renders a blank screen for anyone with reduced motion, a backgrounded tab or a
   paused compositor, and reads as a data-loading bug.
3. Change reduced motion from `animation: none` to `animation-duration: 1ms` → the removal check
   must fail. **34-03 found this exact gate matching `animation: none` from a *neighbouring* rule
   within 400 characters — verify the check is anchored to the right block.**
4. Disable the entrance entirely → the **positive** half must fail. A motion system shipped as dead
   CSS passes every stillness assertion ever written.
5. Re-measure tilt per pointer-move → the rect-count assertion must fail.

> `test.use({ reducedMotion })` **is not typed on this suite's extended fixture and had no runtime
> effect** — the "reduce" pass ran with no preference set while still reporting `reduce` in its
> name. Verify the preference actually applied before trusting either direction.

## Out of scope

New motion tokens or classes (D-38-01). Any 3D beyond CSS depth — no WebGL, no scene graph, no
physics runtime; `dependency-budget.test.ts` forecloses three.js **by name**, so a future reader
sees the option was considered and rejected at ~600kB rather than never raised.
