# 38-16 — Performance

## Goal

Prove the phase cost the product nothing it did not choose, and say plainly what was not measured.

## Why

The baselines exist and are unusually honest, which makes them worth defending.

- **24 runtime dependencies. Phase 34 added zero.** `dependency-budget.test.ts` (31 tests)
  forecloses three.js and friends **by name**, with a recorded negative control:
  `"three": "^0.160.0"` added → failed both the denylist and the baseline → removed.
- **Phase 34's CSS delta: +5,821 B** (comments stripped; 46% of `globals.css` is comment and none
  of it ships). New JS: 24,000 B of source across 6 files.
- **Against those additions, one removal.** 34-03 took `PageTransition` out of the tenant shell,
  orphaning `framer-motion` entirely. It remains in `package.json` but is reachable from no route,
  so it no longer ships — a saving that comfortably exceeds every addition.
- **`usePointerTilt`'s cost is asserted by counting calls**, not by reading source: 1
  `getBoundingClientRect` across a 50-move burst, ≤ 2 `setProperty` per animation frame across a
  100-move burst. A hook that re-measures per move benchmarks beautifully in isolation and stutters
  on a real page; only counting makes that visible.
- **POS tap-to-cart: 79–99 ms**, two runs, on the real path with an open till.

And one thing 34-08 recorded as **not measured, without pretending otherwise**: a true pre-phase
**built** bundle comparison, because that means checking out the pre-phase tree and building it in
a working tree shared by several agents. This plan inherits that limitation and states it again
rather than quietly dropping it.

## Tasks

1. **Re-baseline the bundle** after waves 1–5: `globals.css` comments-stripped, new JS source,
   dependency count. Record the delta against phase 34's figures.

2. **Dependency budget: zero additions.** No charting library for a sparkline (inline SVG, phase
   21's precedent). No table library beyond the installed `@tanstack/react-table`. No animation
   runtime.

3. **`framer-motion`.** 38-13 deletes the orphaned page-transition island. The package stays in
   `package.json` — `dependency-budget.test.ts` deliberately fails if it is removed without
   updating the baseline in the same commit. Either do both together or neither.

4. **Re-render cost on the two screens that matter.** Count renders on a POS cart mutation and a
   KDS ticket state change. `DataGrid` must not re-render every row on a sort or a filter.

5. **`--motion-loading` shimmer** must not run on operational surfaces (34-05) — a perpetual
   animation is a permanent paint. Verified in 38-12; re-verified here as a performance property.

6. **Re-run the operational latency observation** on the real path with an open till — reaching it
   requires opening a till through the real UI first, because the menu grid is gated on one and no
   seed provides it. 34-08 learned this after several attempts measured a *"Your till is closed"*
   empty state.

7. **Gate G13** — CSS/JS above baseline, or any new runtime dependency.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| Dependency count | unit | **24**, unchanged |
| Denylist | unit | three.js and friends still foreclosed by name |
| CSS delta | unit | recorded against phase 34's 23,195 B baseline; a rise is justified in the summary or it fails |
| Re-render count | unit | POS cart mutation re-renders the cart, not the grid; `DataGrid` sort re-renders rows once |
| Operational animations | e2e | 0 on POS and KDS, including during suspense |
| Containing-block creators | e2e | 0 on POS and kitchen routes |
| Tilt cost | unit | rect and `setProperty` call counts unchanged |
| Tap-to-cart | e2e | **observation, recorded, never the gate** |

### Negative controls — observe each failing

1. Add `"three": "^0.160.0"` → denylist **and** baseline red. Remove.
2. Add 2 kB of CSS → delta red.
3. Re-measure tilt per pointer-move → rect-count red.
4. Add a shimmer to a POS skeleton → operational-animation red.
5. Point the latency spec at a closed till → it must fail loudly, **not** report the empty state's
   render time as a latency. 34-08 found a settle signal waiting on a `cart-lines` testid that does
   not exist: it spent its full timeout and reported a **20-second "latency"**, and a sibling check
   queried `null`, returned `[]` and asserted nothing.

## Stated limitations — carried forward, not dropped

- **No true pre-phase built-bundle comparison.** Same reason as 34-08: it requires building a
  checked-out pre-phase tree in a working tree shared by several agents.
- **The tap-to-cart figure is not a gate.** It is wall-clock from developer hardware on a shared
  machine and would fail differently on every machine. The gates are the deterministic
  computed-style assertions, which fail identically everywhere.
