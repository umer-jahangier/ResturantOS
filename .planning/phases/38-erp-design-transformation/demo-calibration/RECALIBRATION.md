## Executive summary

**The good news is bigger than expected.** The demo's accent set is genuinely accessible
(gold-on-surface 7.61:1, teal-on-surface 8.99:1, bg-on-gold 8.91:1 — all AA), it contains
**zero `backdrop-filter`** and **zero custom easing**, and its whole motion language is smaller
than ours already is (150 ms hover, a 1 px lift, border-colour as the hover signal). The circular
theme reveal the owner asked for is **already installed** — `@teispace/next-themes@2.0.3` ships
`transition="circular"` with cursor origin, automatic reduced-motion suppression and a silent
no-op on unsupported engines. It is **one prop on one file**, zero new dependencies.
And all three fonts exist in `next/font/google` (`DM Mono` is not variable — weights must be
declared explicitly, or the build fails).

**Four things are hard, and three of them are not colour.**

1. **The demo's neutrals are not its brand hue.** Its surfaces sit at hue **256–270** (cool
   blue-black, chroma 0.028–0.052) while its accent is gold at hue **69**. Our
   `globals.css:331-343` ties all thirteen `--neutral-*` stops to `var(--brand-h)` at chroma
   ≤ 0.010, and `design-tokens.test.ts:289-291` *enforces* it. Setting `--brand-h: 69` gives us
   warm brown-grey surfaces, not the demo's blue steel. **There is no option that keeps both the
   demo's look and the one-number claim.** This must be decided in writing before a token moves.

2. **A hue swap alone does not produce gold.** The chroma column was gamut-clamped for hue 195;
   at hue 69 the same chromas use only 65–78 % of the sRGB boundary and render `#e1aa6a` — tan.
   Chroma must be re-derived. Do it in **the same edit** as the hue move: two rounds of
   number-recording is how a drift gate gets loosened "temporarily".

3. **Seventeen of the demo's headline numbers cannot be honestly computed today**, and the
   most seductive panel in the file — the Menu Margin Ranking — is a *ranking built entirely on a
   column that is NULL for every row*. The codebase already carries three separate guards against
   exactly this (`ReportCatalog.java:74-80`, `ReportTable.tsx:22-34`,
   `owner-dashboard.tsx:52-65`, which hardcodes `value="—"` for gross margin). Any redesign that
   paints a P&L card is re-introducing the defect class this project has already paid for.

4. **The phase is restarting on top of four RED conformance gates.** G1 type-scale 1,118 vs a cap
   of 961; G2 139 vs 137; G3 145 vs 142; G4 44 vs 43 — 17 files born off-contract during the
   post-audit S0 repair drive. The gates were the phase's central mechanism and nobody ran them.
   Re-baselining is wave 0, not a chore for later.

**The one thing to be ruthless about on the operational zone.** `.screen { animation: fadeIn
0.25s ease }` at `Docs/NEXUS_ERP_Demo.html:189` is on `#screen-pos` itself, and its keyframe
carries `transform: translateY(6px)`. Copying it is simultaneously (a) a forbidden entrance
animation, (b) a running animation against a gate that currently measures **0**, and (c) a
`transform` on an ancestor of `.receipt-root`, which prints the sidebar onto a customer's bill.
That is one line of CSS that breaks the containment gate and the print gate together. The demo
also has **no KDS at all** — 11 screens, none of them kitchen — so anything proposed for the
board "from the demo" is an invention, not a calibration.

**Ordering, stated plainly.** Tokens, fonts, the type bridge and the theme animation all land in
`frontend/app/globals.css`, `frontend/app/layout.tsx` and
`frontend/components/providers/theme-provider.tsx`. Those are **shared files**. Foundation work
**cannot run concurrently with module work**, and the hue+chroma edit cannot even run concurrently
with the font edit if both touch `globals.css` in the same window. Waves 0–2 are serial by
construction; waves 3 onward are parallel-safe only because their file sets are disjoint.

## 7. The five things most likely to go wrong

1. **Someone sets `--brand-h: 69`, sees tan, and raises chroma in a second commit.** The drift gate
   then gets re-recorded twice, and the second recording is done by a person who already believes
   the numbers are noise. Hue and chroma are **one edit**.
2. **Someone ports `.screen`'s fadeIn to get the demo's page feel.** It is six lines of CSS and it
   prints the sidebar onto a customer's receipt.
3. **Someone builds the demo's Finance screen because it is the most beautiful one in the file.**
   Every number on it is NULL in our fact table, and the codebase already refuses three of them.
4. **Someone starts with the dashboard because that is where the demo looks best.** D-38-03 exists
   because a restaurant loses money when the POS is wrong and loses nothing when the dashboard is
   plain.
5. **Someone runs module work in parallel with the token edit** because both "look like frontend
   work". They are not: one is a shared file that redefines what the other is measured against.
