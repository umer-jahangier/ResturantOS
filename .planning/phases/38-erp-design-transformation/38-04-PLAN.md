# 38-04 — The POS terminal

## Goal

Give the cashier the screen back, at every width, without spending one millisecond or one
compositing filter on decoration.

## Why

Brief §15: *"one of the most important screens. Speed > decoration."* §65 puts functionality and
usability above visual polish. The audit found the desktop POS workable and the rest of it not.

- **The POS renders inside the back-office shell** — 255px sidebar, breadcrumb `App › POS`, global
  search, branch pill, avatar. Phase 20 UI-SPEC §4.1 called a separate operator shell *"the single
  biggest structural change"*; it was never built.
- **At 390px the POS is broken.** The cart panel overlays the menu grid: category chips render as
  `Sta…`, `Ma…`, `Dri…`, menu tiles are sliced vertically, and the till bar wraps mid-value
  (`Float: Rs` / `5,000.00`). `evidence/shots/pos-mobile-light.png`.
- **Product cards carry name and price only** — no image, no availability, no modifiers, no
  quick-add (§15).
- The cart panel measures **~300px** against UI-SPEC §3.10's declared **360px**, *"too narrow for a
  modifier line plus quantity stepper plus money without truncation."*
- `components/pos/till-session-bar.tsx` carries **15 raw palette literals** — the worst file in the
  product — and renders as a pale-green band across the top of the terminal, off-theme and
  unmeasured.
- `h1Count = 0`.

**And what is right, and must stay right.** Measured today on the live route: **0 containing-block
creators, 0 running animations, 0 compositing filters.** Phase 34 measured tap-to-cart at 79–99 ms.

## Tasks

1. **Operator chrome.** On `app/(tenant)/app/pos/**`, collapse the shell to a 56px operator strip:
   branch, till state, user, exit. No sidebar, no breadcrumb, no global search. Reclaim ~255px of
   horizontal space for the tile grid. `PageBody fullBleed`.

2. **Cart panel to 360px**, with room for a modifier line, a quantity stepper and money without
   truncation.

3. **Product card contract** — name (`--text-pos`, 17/24, weight 500) · price · image where the
   menu item has one · availability · quick-add. Minimum tile 56px on both axes.

4. **Touch.** Every interactive target **≥ 44 × 44px**. Every hover behaviour gets a
   touch/click equivalent (§16). Verify at 768 and 1024, the widths a POS tablet actually runs at.

5. **390px layout.** Order panel becomes a bottom sheet with a persistent total bar; the tile grid
   goes full-width. Not a shrunk desktop layout — a different one.

6. **`till-session-bar.tsx`**: 15 emerald literals → `--success-*` role tokens, both themes.

7. **`PageHeader`** so `h1Count === 1`.

8. **Feedback discipline.** Tile press → ≤120 ms scale/highlight at `--motion-state`. **Cart
   mutation animates nothing** — `--motion-instant`.

## Zone: `operational`. What this plan may not do

No `backdrop-filter`. No entrance animation. No parallax. No pointer tilt. No page transition. No
perpetual animation — including a shimmer arriving through a shell suspense boundary (34-05).
No glass on any component the POS imports, including a shared `Card`.

**And the reason it matters beyond frame rate:** `transform`, `filter`, `backdrop-filter`,
`perspective`, `will-change` and paint/layout `contain` each make an element the containing block
for its `position: fixed` descendants — **at print time as well as on screen**.
`components/print/receipt-print.css:181` lifts the bill out of the app shell with
`position: fixed`, and that route lives under `app/pos/`. A glass header on this screen prints the
application onto a customer's bill.

### Negative controls — observe each failing

1. Add `transform: translateZ(0)` to the POS layout → containing-block gate red **and** the print
   gate red. This is the single most important control in the phase: watch **both** go red.
2. Restore `body * { visibility: hidden }` without `!important` in `receipt-print.css` → print gate
   red, with sidebar text in the extracted PDF.
3. Set `@page size: 80mm auto` → print gate red on page size (Chromium silently drops the
   declaration and prints US Letter).
4. Add `transition: height` to a cart line → cart-geometry gate red.
5. Add `.vdl-enter` to a tile → animation gate red.
6. Render the desktop two-column layout at 390px → 390px integrity red.

> **The 99 ms is not a gate and must not be quoted as one.** It is a wall-clock figure from
> developer hardware on a machine shared with several agents; it would fail differently on every
> machine. The gates are the deterministic computed-style assertions.

where the menu item has none — **do not generate placeholder food photography**; the card renders
without an image slot.
