# 38-07 — Inventory, menu and purchasing

## Goal

The widest module family in the product, on one grid, readable on a phone, with alerts that do not
depend on colour.

## Why

This family owns most of the hand-rolled tables and most of the sub-44px targets.

| Screen | Measured |
|---|---|
| `/app/purchasing/purchase-orders` | **108** interactive controls < 44px; 84 rows unpaginated; PO number is a truncated UUID (`ca6ed037…`); "Expected date" is an em-dash on **all 84 rows** |
| `/app/purchasing/vendors` | **63** controls < 44px |
| `/app/inventory/ingredients` | **62** controls < 44px |
| `/app/inventory/stock` | **30** controls < 44px; **100 elements past the viewport at 390px**, **42 at 1024px**; row heights **65px and 81px** in one table; `thead` `position: static` |

Raw `<select>` concentration is also here — `IngredientFormDialog.tsx` **12**,
`RecipeFormDialog.tsx` **4**, `app/inventory/recipes/[menuItemId]` **3** — but that migration
belongs to **phase 35**, not this plan.

And one thing the product currently states without explanation: `/app/inventory/stock` renders
**Chicken −2987 KG** and **Total stock value: −Rs 2,116,690.70**. Whether the figure is right is an
inventory question. That the UI presents a negative quantity as an ordinary number is a design
question, and this plan owns it.

## Tasks

1. **Migrate to `DataGrid` + `FilterBar`:** `/app/inventory/{stock,ingredients,categories,coverage,recipes,setup}`,
   `/app/menu/items`, `/app/purchasing/{purchase-orders,vendors,invoices,payments,order-suggestions}`.
   Sticky headers, one row height per table, pagination, card fallback below `md`.

2. **PO number becomes a human identifier.** Drop the all-em-dash "Expected date" column
   (`DataGrid` refuses to render it anyway). Paginate the 84-row list.

3. **Low-stock and out-of-stock alerts** — icon + text + colour, three channels (UI-SPEC §4.2).
   Visually obvious on the rows that matter without alarming every row.

4. **Negative on-hand gets a stated reason.** A negative quantity or valuation renders with an
   inline explanation or a `Why?` affordance, never as an ordinary number. This follows the
   `/app/finance/takings` standard: *"it will not show you a zero it does not mean."*

5. **Bulk actions** — archive, activate/deactivate, export — with `{n} selected` always visible and
   `ConfirmDialog` naming the count.

6. **Menu availability toggles** — immediate optimistic visual feedback plus a toast; on failure,
   revert and say why (brief §21).

7. **Product cards** on `/app/menu/items` — image where the item has one, name, price, category,
   availability. **No placeholder food photography.**

8. `PageHeader` on every screen in the family; targets to 44px.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| Grid conformance | e2e | sticky header, one row height ∈ {32,44}, pagination, on every migrated route |
| **Target size** | e2e | 0 controls < 44×44 on all migrated routes at 390 / 768 / 1024. Baselines: PO 108 → 0, vendors 63 → 0, ingredients 62 → 0, stock 30 → 0 |
| **Mobile integrity** | e2e | at 390px: 0 `<table>` elements, **0 elements past the viewport** (stock baseline 100 → 0) |
| Identifier column | unit | no UUID-shaped PO number renders |
| Empty column | e2e | "Expected date" is not in the DOM |
| Alert channels | unit | low-stock and out-of-stock each render icon + text + colour |
| Negative quantity | unit + e2e | a negative on-hand renders an explanation; asserted against the real `−2987 KG` row |
| Availability toggle | e2e | optimistic update + toast; forced failure reverts and states the reason |
| Type/radius/literal conformance | unit | G1, G2, G3 baselines decrease |

### Negative controls — observe each failing

1. Render the desktop table at 390px → mobile integrity red (should reproduce the 100-element
   baseline).
2. Set one row's padding differently → row-height uniformity red.
3. Render low stock as colour only → alert-channel red.
4. Render `−2987` with no explanation → negative-quantity red. **Watch this fail against today's
   code first.**
5. Force the availability mutation to reject → the toggle must revert; if it stays flipped, red.
