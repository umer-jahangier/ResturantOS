# 38-01 — The type and space bridge, `PageHeader` and `PageBody`

## Goal

Make the phase-20 type and space scales **reachable**, and give every page one heading component
and one padding owner.

## Why this is plan 01 and nothing else can go first

`app/globals.css:526-533` declares the eight type roles and seven space steps, then deliberately
withholds them from `@theme` because bridging would re-typeset ~700 call sites at once. The audit
measured the consequence:

- **986** Tailwind type-scale classes against **1** contract-token class;
- `--text-body` (15px) renders on **22 text nodes** in the entire product, while 14px renders on
  **1,901** and 12px on **686**;
- **12** distinct font sizes ship against a contract of 8 roles, including 12.8px, 10px and 18px
  which are in no contract at all;
- **145** bare `rounded` call sites resolve to Tailwind's 4px default and bypass `--radius`
  entirely — the most-used radius in the product is the one that is not in the design system;
- **60** files declare their own `<h1>`, there is no `PageHeader`, and **4 screens have no `<h1>`
  at all** (`/app/pos`, `/app/pos/tills`, POS order management, `/app/hr/attendance`);
- `app/(tenant)/layout.tsx:105` hard-codes `p-4 lg:p-6 pb-20 md:pb-6` on `<main>`, so no page can
  be full-bleed — which the POS, the KDS board and a floor plan all need.

The withholding decision was correct when it was made. It has now expired: every downstream plan
would otherwise re-litigate the same argument screen by screen, and the 986:1 ratio would survive
the phase.

## Tasks

1. **Bridge `--text-*` and `--space-*` into `@theme`**, keeping every declared value identical.
   Publish `text-display`, `text-h1`, `text-h2`, `text-body`, `text-small`, `text-label`,
   `text-pos`, `text-kds` as utilities carrying **size and line-height together**, so a call site
   cannot take one without the other.

2. **Write the legacy mapping and apply it to the ten densest screens.** Not a blanket
   find-and-replace — `text-xs` means `--text-label` where it is a column header or chip and
   `--text-small` where it is prose, and the two are different sizes. Record the mapping in
   `frontend/docs/typography.md` beside the roles.

3. **`PageHeader`** — title (`--text-h1`, exactly one `<h1>`), optional description, meta row, one
   primary action, overflow menu. Adopt on the ten screens migrated in task 2, including the four
   that render no `<h1>` today.

4. **`PageBody`** — owns the page gutter (`lg` below 1024px, `xl` at and above), with a
   `fullBleed` opt-out. Move the padding off `layout.tsx:105`. The POS, KDS and floor-plan routes
   take `fullBleed`.

5. **Radius convergence on the migrated screens**: bare `rounded` → the ladder token the surface
   actually wants. Do not "round everything the same"; §8 of the brief asks for larger radii on
   cards and dialogs and smaller on compact controls.

6. **Gates G1, G2 and the `h1` half of G12** (UI-SPEC §11.1), each with a per-file baseline that
   may only decrease.

### Negative controls — run these, watch them go red, record the observation

1. Add `text-2xl` to a migrated file → **G1 must fail**. Restore.
2. Add `rounded` to a migrated file → **G2 must fail**. Restore.
3. Delete the `<h1>` from `PageHeader` → **G12a must fail**. Restore.
4. Change `--text-body` to 14px → the token test must fail on **both** size and line-height, not
   just size. Restore.

> A gate that has not been watched failing is not evidence. Six gates in phase 34 passed against
> known-broken code, including the positive control, which had been *skipping* for weeks.

## Out of scope

Migrating all 65 routes. Each later screen plan migrates its own — that is deliberate, so a
regression is attributable to one screen rather than to one enormous commit.

## Risk

A 15px body where 14px shipped changes line counts on every list screen. That is the intended
change and it is why task 2 is ten screens with screenshot evidence, not all sixty-five.
