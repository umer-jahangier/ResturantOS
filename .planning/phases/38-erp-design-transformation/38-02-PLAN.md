# 38-02 — `DataGrid` and `FilterBar`

## Goal

One enterprise data table, capable enough that no screen has a reason to hand-roll another.

## Why

The largest structural defect the audit found.

- **37 files hand-roll a `<table>`. 4 files import `components/ui/data-table.tsx`.** The 33
  others include every finance table (`AccountTable`, `GeneralLedger`, `JournalEntryTable`,
  `ApAgingTable`, `ArAgingTable`, `TransactionRegister`, `TillVariancePanel`, `TenderSplit`,
  `TransactionLedgerLinks`) and 16 route files.
- Measured live on `/app/inventory/stock`: `thead th` computed `position` is **`static`**; row
  heights inside one table are **65px and 81px**; **0** selection checkboxes; **no pagination**.
  Across all 12 rendered tables in the sweep: **sticky headers = 0**.
- `/app/purchasing/purchase-orders` renders **84 rows** in one ungated list, with a **PO number
  column showing truncated UUIDs** (`ca6ed037…`) and an **"Expected date" column that is an
  em-dash on all 84 rows**.
- At 390px the desktop table is dropped in unchanged: **100 elements past the viewport** on
  `/app/inventory/stock`, values sliced mid-word (`90 EACI`, `213.5 K`, `-2987 K`). Brief §57:
  *"do not force desktop tables onto mobile."*
- **108 interactive controls below 44px** on the purchase-order screen — the worst in the product.

## Tasks

1. **`DataGrid`**, extending the existing `data-table.tsx` rather than replacing it, so its four
   current call sites keep working: sticky header at `--z-sticky`; density prop (`compact` 32px /
   `comfortable` 44px, one value per table); pagination (25/50/100 with `Page N of M`), switching
   to `@tanstack/react-virtual` above 200 rows; row selection with an always-visible
   `{n} selected`; column visibility; per-column sort; loading / empty / **filtered-empty** /
   error states.

2. **The responsive card fallback.** Below `md`, `DataGrid` renders a card list — primary line,
   secondary line, trailing value, row menu — not a horizontally scrolled table. This is the
   single change that fixes mobile across thirty screens at once.

3. **Two content rules, enforced by the component:**
   - an **identifier column renders a human identifier** (PO number, order number, SKU). Passing a
     raw UUID is a type error, not a style choice;
   - a column whose every visible row is empty **is not rendered**.

4. **`FilterBar`** — chips, individually removable, `Clear all`, persisted per screen:
   `Branch: Islamabad · Date: Aug 1–12 · Status: Completed  [Clear all]`.

5. **Bulk actions** — destructive bulk actions route through `ConfirmDialog` (38-03) and name the
   count: *"Archive 12 ingredients?"*

6. **Migrate three reference screens** end-to-end — `/app/inventory/stock`,
   `/app/purchasing/purchase-orders`, `/app/inventory/ingredients` — so the component is proven
   against real data before waves 3–4 depend on it.

7. **Gate G4** (pattern duplication): `<table>` implementation count may only decrease.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| Sticky header | e2e | `thead th` computed `position === "sticky"` on all migrated screens |
| Row height uniformity | e2e | exactly **one** distinct row height per table; ∈ {32, 44} |
| Pagination | e2e | 84-row PO list renders ≤ 50 rows + a pager |
| Card fallback | e2e | at 390px, `table` count is 0 and 0 elements extend past the viewport |
| Target size | e2e | 0 interactive controls < 44×44 on migrated screens at 390 and 768 |
| Identifier column | unit | passing a UUID-shaped value without a display field fails the type check |
| Empty column | unit | an all-empty column is not in the DOM |
| Filtered-empty ≠ empty | unit | the two states render different copy (UI-SPEC §8.3) |
| G4 | unit | `<table>` count ≤ baseline − 3 |
| Keyboard | e2e | arrow-key row focus; focus `scrollIntoView({block:"nearest"})`; visible outline |

### Negative controls — observe each failing

1. Set `thead` to `position: static` → sticky check red.
2. Give two rows different padding → uniformity check red.
3. Render the table (not cards) at 390px → overflow check red.
4. Pass a bare UUID as the identifier column → type check red.
5. Add a fourth hand-rolled `<table>` → G4 red.
6. Make filtered-empty reuse the empty copy → copy check red.

> **Do not anchor any of these on a route whose data comes from a service that can be down.**
> `hr-service` was `503` for the whole audit; a gate anchored there passes vacuously by skipping.
> `/app/inventory/stock` and `/app/purchasing/purchase-orders` were both reachable, repeatedly.

## Out of scope

Migrating the other 30 tables — waves 3 and 4 do that, per screen family. Server-side filtering
where the endpoint does not accept the parameter (audit §12).

## Zone note

`DataGrid` is consumed by `restrained` **and** `operational` surfaces. It therefore carries **no**
glass, **no** entrance animation and **no** hover translate by default. A shared component
enriched for the dashboard is how the POS acquires a compositing filter nobody chose.
