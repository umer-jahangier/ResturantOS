# 38-03 — One `StatusBadge`, one `ConfirmDialog`, and the visual form contract

## Goal

Collapse six status badges into one and six confirmation dialogs into one, and fix the two form
defects the audit actually found — rather than the ones it did not.

## Why

**Six status-badge implementations:** `components/ui/status-badge.tsx`,
`components/purchasing/PoStatusBadge.tsx`, `components/pos/payment-status-badge.tsx`,
`components/pos/sync-status-badge.tsx`, `components/platform/tenant-badges.tsx`,
`components/finance/PeriodStatusChip.tsx`. 43 files reference one of them. Two of the six
(`PoStatusBadge` 6, `PeriodStatusChip` 2) are among the raw-palette-literal offenders, so they do
not follow the theme or `--brand-h`.

**Six confirmation implementations and no primitive.** `grep -rl 'AlertDialog\|ConfirmDialog'`
returns **0**. Confirmation is nonetheless implemented six times as a bespoke `Dialog` plus a
local handler: `app/(tenant)/app/stations/page.tsx:192`,
`app/(tenant)/app/purchasing/vendors/[id]/page.tsx:413`,
`app/(tenant)/app/inventory/setup/page.tsx:345`,
`app/(tenant)/app/inventory/ingredients/page.tsx:335`,
`app/(tenant)/app/inventory/categories/page.tsx:257`,
`components/pos/void-refund-dialog.tsx:143`.

Brief §50 is behaviourally satisfied and structurally violated. §62 requires that if one delete
confirms, all equivalent deletes confirm — six independent copies is exactly how that stops being
true.

**What the audit found about forms, and what it did not.** Both dialogs that could be opened were
probed: New Purchase Order (6 inputs) and Add table (3 inputs). **Zero unlabelled inputs. Zero
placeholder-as-label.** Brief §22's most-quoted rule is already honoured, and this plan will not
pretend otherwise. What *is* missing:

- **`requiredMarked: 0`** in both dialogs — no required-field indication at all;
- **`aria-modal` is `null`** on every dialog probed, including the command palette;
- `/app/hr/attendance` has **6 inputs with no label, no `aria-label`, no `aria-labelledby`** and
  **3 interactive controls with no accessible name** — one screen, from source only, because
  `hr-service` was down.

## Tasks

1. **One `StatusBadge`.** Icon + text + colour, three channels, always (UI-SPEC §4.2). One
   semantic map from domain status → `{icon, label, tone}`, `--text-label` type, semantic role
   tokens only. Migrate all six call-site families; delete the five duplicates.

2. **One `ConfirmDialog`.** Props: `title`, `body`, `confirmLabel`, `tone`, `onConfirm`. The
   confirm button **restates the verb** — `Void payment`, never `OK`. Migrate all six sites.

3. **The confirm/undo boundary** (UI-SPEC §8.2). Confirm only what is destructive or irreversible.
   **Never** confirm save, availability toggle, filter, sort or navigate. Where the action is
   safely reversible, prefer a toast with an action: `Product archived. [Undo]`.

4. **Required-field indication** — visual marker plus `aria-required`, in the shared form field.

5. **`aria-modal="true"`** on every dialog surface, including the command palette.

6. **`/app/hr/attendance` labelling.** Six inputs get labels. **Re-audit this screen in a browser
   against a running `hr-service` before executing** — its defects are source-derived only, and
   the audit says so.

7. **Gate G4** extended: `StatusBadge` and `ConfirmDialog` implementation counts may only decrease.
   **Gate G12** extended: unlabelled inputs and unset `aria-modal`.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| One badge implementation | unit | G4: exactly 1 `StatusBadge`; the other five files are gone |
| Three redundant channels | unit | every status variant renders an icon, a text label and a tone — asserted per variant, not per component |
| One confirm implementation | unit | G4: exactly 1 `ConfirmDialog`; six call sites use it |
| Confirm copy | unit | confirm label is never `OK`/`Yes`/`Confirm`; body names the object |
| Harmless actions do not confirm | e2e | toggling menu availability opens no dialog |
| Required indication | unit + e2e | every required input has a visual marker and `aria-required` |
| `aria-modal` | e2e | set on every dialog, palette included |
| Labels | e2e | 0 inputs without an accessible name on every reachable route |

### Negative controls — observe each failing

1. Reintroduce `PoStatusBadge.tsx` → G4 red.
2. Render a status variant with colour only (strip the icon) → three-channel check red.
3. Set a confirm label to `OK` → copy check red.
4. Wrap the availability toggle in a confirm → harmless-action check red.
5. Remove `aria-required` from one field → required check red.
6. Remove `aria-modal` from one dialog → `aria-modal` check red.
