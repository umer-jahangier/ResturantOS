# 38-05 — The Kitchen Display System

## Goal

A board a cook can read at two metres, that never lies about how late a ticket is, and whose
counters do not overlap.

## Why

Phase 21 did the hard, correct work here: four-channel ageing (border width 2/4/6px, distinct icon
**shape**, literal chip text, and a **card fill change** for late), one item per line at
`--text-kds`, modifiers bold beneath their own item, and a board that can finally report failure.
The test asserts the card carries **no** `bg|text|border-(gray|red|amber|emerald|blue)-\d+` class
at all. **None of that is reopened.**

What the audit found on the live board:

- **The station counters collide.** `PREPARING` and `READY` overlap into `PREPARINGREADY` on both
  station cards, in both themes, at 1440px — the widest viewport tested.
  `evidence/shots/kitchen-index-desktop-light.png`.
- **A dark board floating in light chrome.** The `[data-surface="kds"]` board begins at x=280 with
  the light sidebar and light top bar around it. UI-SPEC §4.1 said this should be removed
  structurally rather than patched; `station-board.tsx` currently fights the shell.
- **`Oldest 113h 52m`.** `components/kds/station-picker.tsx:83` formats elapsed time with no upper
  bound and `:270` renders it. Tickets from 2026-08-07 present as urgent work, visually
  indistinguishable from a ticket that is genuinely two minutes late. The dashboard repeats it as
  `114:01:07` under "ACT NOW".
- Two station cards occupy the top 300px of a 900px viewport; the rest is empty.
- `components/kds/station-board.tsx` carries 3 raw `<select>` and 2 raw palette literals.

## Tasks

1. **Re-lay-out the four station counters** (NEW / STARTED / PREPARING / READY) so labels cannot
   collide at any width. The counter block gets a minimum column width derived from the longest
   label, and the label wraps or abbreviates by rule — never by overflow.

2. **The board owns its viewport.** `PageBody fullBleed` on the kitchen routes; station header
   only, 48px. The board stops fighting the shell with `min-h-screen`.

3. **Bounded elapsed-time formatting.** Above 24h, render an **absolute date and time** and drop
   the urgency treatment. A four-day-old ticket is not "ACT NOW"; presenting it as such trains
   cooks to ignore the colour that matters. Shared with 38-09 (dashboard) so both surfaces use one
   formatter.

4. **Column layout (§18):** NEW · PREPARING · READY · COMPLETED, adapting count to viewport, with
   counters that update in place.

5. **Station index density** — cards sized to the content, board filling the height, so two
   stations do not leave 600px of void.

6. **Token convergence** — 2 raw palette literals out of `kds-item-column.tsx` /
   `kds-ticket-card.tsx` to `--kds-*`.

7. `PageHeader` on the station index; the board itself keeps its station header.

## Zone: `operational`. What this plan may not do

No `backdrop-filter`, no entrance animation, no parallax, no tilt, no attention-seeking loop.
Brief §18: *"avoid distracting animations."* Critical alerts are obvious by **fill and border**,
which is the most robust encoding available and already implemented.

State changes update **in place** — a ticket moving column must not re-enter with an animation
that costs a cook their place on the board.

### Negative controls — observe each failing

1. Set a counter label container to `width: 40px` → collision check red. **This is the control
   that matters: the defect exists today, so write the check first, watch it fail against the
   current code, then fix.**
2. Remove the 24h bound → elapsed formatting red at the 24h01m case.
3. Add `.vdl-enter` to a ticket card → animation gate red.
4. Add `backdrop-blur` to the station header → containing-block gate red.
5. Drop item font-size to 18px → legibility red.

> **Do not anchor these gates on a dashboard or any surface that renders an error when a service
> is down.** Phase 34's positive control was anchored that way and *skipped* silently for weeks
> while reporting green. Anchor on the board element itself, and assert it is attached.
>
> **`kitchen-service` was `UP` during this audit but has been `DOWN` before** — 34-08 could not
> run the KDS half of its latency spec for exactly that reason, and said so. If it is down at
> execution time, the plan reports the gate as **not run**, never as passed.

## Out of scope

Bump-bar hardware. Ticket routing logic. Station configuration behaviour. The
`getAgingTreatment` fraction logic, which scales with each station's own
`escalationThresholdSeconds` and is more principled than the industry's fixed 5/8-minute
convention — **keep it byte-identical**.
