# 38-12 — The four data states, everywhere

## Goal

Close the gaps. Do not rebuild the parts that already work, and there are many.

## Why — and what is already right

Phase 14b and 34-05 did this well, and the audit confirms it live:

- **Skeletons, not spinners.** 34 files import a skeleton; only **8** `animate-spin` occurrences
  remain, in 8 files. The skeleton is **zone-aware** — it shimmers on back-office surfaces and
  sits still on operational ones, because a perpetual animation may not run on a POS terminal even
  when it arrives through a shell suspense boundary.
- **Error copy is already correct.** Measured live: *"Couldn't load the employee roster. This
  module is temporarily unavailable. Try again in a moment."* + `[Try again]`. Never a status code.
- **The error box gained depth and nothing else** (34-05). Character may only be added in the
  direction that **raises** salience: a raised surface reads as more urgent than a flat one.
  Softening a failure is how phase 14b's defect — eleven screens telling an owner his business had
  no vendors while the service was down — comes back with better typography.
- **Toasts are mounted and used**: `app-providers.tsx:28`, `<Toaster richColors position="top-right"/>`,
  **184 call sites** (94 `.error`, 93 `.success`, 3 `.info`, 1 `.warning`).
- **`QueryBoundary` is adopted by 49 files**; `EmptyState` by 30.

## What is actually missing

1. **18 files destructure `isLoading` with no error path at all** — including
   `app/(tenant)/app/{reports/[code],reports/fbr,purchasing/analytics,dashboard/realtime}/page.tsx`,
   `components/reporting/{ReportTable,FbrTaxSummaryCard,DashboardTileGrid}.tsx`,
   `components/pos/{menu-grid,table-floor-view}.tsx`, `components/crm/customer-detail.tsx`,
   `components/shared/{top-bar,uom-select,catalog-item-combobox}.tsx`,
   `components/purchasing/VendorScorecardCard.tsx`, `components/finance/OpenPeriodDatePicker.tsx`.
2. **Filtered-empty is not distinguished from truly-empty** anywhere. `No purchase orders yet`
   and `No purchase orders match these filters` are different problems with different next actions.
3. **8 remaining `animate-spin`**, including one in the tenant layout that blanks the whole content
   area during bootstrap.
4. **34-05's two gates were never written.** Its own summary says so: *"`state-character.test.tsx`
   and `state-distinguishability.spec.ts` — the plan's two gates — were **not written**.
   Distinguishability is currently argued from the code rather than asserted by rendering both
   states and comparing, which is exactly the standard this phase applied elsewhere and did not
   meet here."*

## Tasks

1. **Error paths for the 18 files.** Each gets a `QueryBoundary` or an explicit `isError` branch
   with cause + `[Try again]` + preserved input.

2. **Per-region boundary granularity** (UI-SPEC §8.1.1), completing 38-09's dashboard work across
   every multi-query screen. A boundary wraps the smallest genuinely-unavailable region.

3. **Filtered-empty as a distinct state** in `DataGrid` and every list: different heading,
   different body, `[Clear all]` instead of a create CTA.

4. **Retire the remaining spinners** to contextual skeletons matched to final dimensions —
   including the tenant layout's bootstrap spinner.

5. **Write 34-05's two gates**, properly: render a forced failure and a forced empty result side by
   side and assert they are **distinguishable** — different role, different copy, different
   affordance. Not argued from source.

6. **Toast consistency** (§28): one severity map, concise message, optional action, dismissible.
   Audit the 184 call sites for `.error` used where `.warning` is meant, and for the reverse.

7. **Localised loading** (§25): `Saving… → Saved`, `Processing payment…`, `Submitting order…`.
   **Never freeze the interface.**

## Verification

| Check | Kind | Passes when |
|---|---|---|
| Error path coverage | unit | 0 files destructure `isLoading` without an error branch. Baseline 18 → 0 |
| **Failure and empty are distinguishable** | e2e | both rendered, compared: different `role`, different copy, different affordance. **This is 34-05's unwritten gate** |
| Filtered-empty ≠ empty | unit | different copy on every list |
| Skeleton dimensions | e2e | skeleton bounding box within 10% of the loaded content's |
| **Skeleton stillness on operational** | e2e | 0 running animations on POS and KDS during a suspense boundary |
| Spinners | unit | `animate-spin` baseline 8 → 0 |
| Error salience | unit | the error surface is not softened: no reduced opacity, no entrance animation, depth ≥ flat |
| No interface freeze | e2e | during a save, the rest of the page stays interactive |

### Negative controls — observe each failing

1. Remove an `isError` branch → coverage red.
2. Make the empty state and the error state render identical copy → distinguishability red.
   **Watch this one especially: it is the gate that was skipped.**
3. Add a shimmer to a POS skeleton → operational stillness red.
4. Add `.vdl-enter` to the error box → salience red.
5. Reuse the truly-empty copy for filtered-empty → red.
