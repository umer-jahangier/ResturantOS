# 38-17 — Consistency audit and regression

## Goal

Re-run the audit that opened this phase, against the same measurements, and answer brief §71's
thirty-five acceptance criteria with evidence rather than assertion.

## Why

`38-AUDIT.md` is a set of numbers taken from a live browser on 2026-08-12. Every one of them is
re-measurable. That is the point: a design phase that ends with a screenshot and an adjective has
proved nothing.

Brief §61 asks for every screen to be inspected for inconsistent padding, typography, colours,
button heights, icon sizes, radius, shadows, alignment and status colours. §62 asks the same of
interactions. This plan does both by **re-running the audit harnesses** and diffing.

## Tasks

1. **Re-run `audit-38.mjs`, `audit-38-reshoot.mjs`, `audit-38-interactions.mjs` and
   `audit-38-a11y.mjs`** unchanged, and diff every measurement against `38-AUDIT.md` §13.

2. **Produce the before/after table** — every count in §13, with its new value, and an explanation
   for any that did not move.

3. **Full gate sweep** — G1…G13 (UI-SPEC §11.1), each with its negative control **observed** and
   the observation recorded in the gate's own docblock, not asserted in a summary.

4. **Visual QA matrix (§63)** — desktop / tablet / mobile × light / dark × loading / empty / error
   / long text / large numbers / large datasets / permission-restricted, across the screen
   families. Sampled and named, not claimed as exhaustive.

5. **Answer §71's thirty-five criteria** individually: met · partially met · **not met, with the
   reason**. A criterion blocked on backend work (audit §12) is marked **not met** and cited — not
   quietly ticked.

6. **Regression:** `npm test`, **`npm run lint`, `npx tsc --noEmit`** — because Vitest does not
   typecheck and a green test run is not a compiling product — plus the full Playwright suite and
   the receipt PDF gate.

7. **Update `SURFACE-MOTION-SPEC.md` §7's gate inventory** with the phase-38 gates and any newly
   discovered vacuous ones. That list is the most useful part of that document and it should keep
   growing.

### The controls that must be observed in this plan specifically

1. **`transform: translateZ(0)` on the POS layout** → containing-block gate **and** print gate both
   red. Two gates, one cause.
2. **`body * { visibility: hidden }` without `!important`** → PDF text contains sidebar strings.
3. **`@page size: 80mm auto`** → PDF page size becomes US Letter (Chromium drops the declaration
   silently).
4. **Disable the entrance vocabulary entirely** → the reduced-motion **positive** half red.
5. **Add a second `<table>`** → G4 red.
6. **Point a gate at a route whose service is down** → it must report **not run**, never green.

## The honesty clause

If a target above is not met, this plan **records it as not met, with the number**, in the phase
summary. It does not round up.

Phase 34 ended with three plans marked `partial` and a definition of done that was explicitly not
fully satisfied — the KDS half of its latency spec did not run because `kitchen-service` was `DOWN`
in Eureka, and the summary said so instead of claiming completion. That is the standard.

Specifically expected to remain unmet, and to be reported as such:

- **§13** KPI comparison data — blocked on `reporting-service`.
- **§17** floor plan states beyond available/occupied — blocked on `pos-service`, and possibly on
  the Floor-View defect 38-06 diagnoses.
- **§19** server/customer/branch order facets — blocked on query parameters.
- **§20** expiry/wastage/valuation columns — fields not populated.
- **§45** personalisation persistence — no preference store.
- **§52** notification centre — `notification-service` unregistered, no listener.
- **§53** activity timeline — no entity-scoped event feed.
- **HR screens** — unauditable while `hr-service` is down; if it is still down, say so.
