# 38-09 — Dashboards, reports and analytics

## Goal

Make the expressive surfaces earn their richness: every chart answers a business question, every
tile that can fail fails alone, and no number is invented.

## Why

34-06 delivered glass portlets, a depth-layered grid, hover lift and a staggered entrance. The
dashboard looks good. The audit found what it *says*:

- **A bar chart that encodes nothing.** `components/dashboard/manager-dashboard.tsx:122` sets
  `fraction: 1` for **every** 86'd item, and `components/dashboard/portlets/portlet.tsx:268`
  renders `width: fraction × 100%`. All three 86'd rows draw a full-width teal bar, always. The
  sibling `stationLoad` at line 112 computes `count / max` correctly — the same portlet renders one
  meaningful bar chart and one meaningless one, **four lines apart**. Brief §47: *"every chart
  answers a business question."* §64: *"do not make dashboards decorative instead of useful."*
- **One error boundary over four queries.** Line 167 wraps `[ordersQuery, ticketsQuery,
  stationsQuery, tablesQuery]` and the entire first KPI row in a single `QueryBoundary`. One
  failing service replaces four tiles with one error box — which is exactly what this audit's
  first screenshot captured, and why §0 of the audit exists.
- **No KPI tile carries a comparison, a percentage change, a trend indicator or a sparkline.**
  Brief §13 requires all five, with the example `Revenue · Rs. 248,500 · +12.4% vs yesterday`.
- **`114:01:07` under "ACT NOW".** Four tickets from 2026-08-07 presented as urgent.
- 34-06 recorded three deliverables as **NOT DONE**: the `TrendChart` dash-offset reveal, the
  count-up number, and the plan's two test files. It also recorded that **§3.4's direct-series-label
  requirement was never verified** — *"its prohibition on colour-only series identification is
  therefore unchecked."*

## Tasks

1. **Delete `fraction: 1`.** Either bind a real fraction to the 86'd portlet or render no bar. A
   bar that is always 100% is decoration wearing a chart's clothes.

2. **Per-portlet error boundaries** (UI-SPEC §8.1.1). A `QueryBoundary` wraps the smallest region
   whose content is genuinely unavailable. A tile whose own query succeeded renders. A tile whose
   query failed shows an inline unavailable state **with its reason** — the pattern the
   till-variance tile already uses correctly (*"No till has been counted yet today"*).

3. **KPI comparison slot, honestly.** Build icon · value · comparison · % change · trend ·
   sparkline. **`reporting-service` returns current values only** — no period-over-period
   aggregate exists (audit §12). Until it does, the comparison slot renders `Not compared yet`
   with the reason. **Do not fabricate a delta** (§68).

4. **Direct series labels** (phase 20 §3.4, still unverified). Every multi-series chart carries
   **direct labels at the line end** or distinct dash patterns/markers. A legend keyed only by a
   colour swatch is a contract violation. **Write the assertion phase 34 did not.**

5. **Bounded elapsed time** — shared formatter from 38-05. Above 24h, an absolute date and no
   urgency treatment.

6. **Reports and analytics screens** onto `DataGrid` where tabular; chart cards get glass and
   depth (expressive zone); loading skeletons matched to final chart dimensions.

7. **Personalisation (§45)** — show/hide and reorder **in session**. Persistence is blocked on a
   per-user preference store (audit §12) and is not built as a facade.

## Zone: `expressive`. What this plan may spend

Glass panels, depth 2/3, hover lift, stagger entrance, pointer tilt on drillable tiles, and the
`--motion-reveal` (620 ms) chart draw-in — all of which exist and are measured. The 420/620 ms
durations exceed the 240 ms ceiling **by zone-scoped extension**: nobody navigates a dashboard 200
times a shift.

Chart reveal runs on **first mount only** — never on a refetch, a websocket push, a filter change
or a period change. `react-countup` is already a dependency, so a careless implementation animates
on every tick; 34-06 flagged this precisely.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| **No constant-fraction bar** | unit | no portlet row is constructed with a literal `fraction: 1`; asserted structurally |
| **Boundary granularity** | e2e | with one of four queries forced to fail, the other three tiles still render |
| Unavailable reason | unit | a failed tile states why; never renders `0` |
| **No fabricated comparison** | unit | with no comparison field in the response, the slot renders `Not compared yet`, never a computed delta |
| **Direct series labels** | e2e | every multi-series chart has a text label per series in the DOM; a legend with swatches and no labels fails |
| Chart reveal once | unit | reveal animation class is absent after a refetch, a filter change and a period change |
| Elapsed bound | unit | shared with 38-05 |
| Reduced motion | e2e | decorative motion **absent**, and the tiles remain **visible** — a blank screen is perfectly still |

### Negative controls — observe each failing

1. Restore `fraction: 1` → constant-fraction check red. **Watch it fail against today's code
   first.**
2. Re-wrap the four queries in one boundary → granularity check red.
3. Compute a delta from a single data point → fabrication check red.
4. Replace direct labels with a swatch legend → series-label check red. **This is the assertion
   phase 34 recorded as never written.**
5. Trigger a refetch and assert the reveal class → reveal-once red.

> **Anchor the boundary-granularity gate on a forced failure you inject, not on a service that
> happens to be down.** Phase 34's positive control was anchored to this very dashboard and
> *skipped* silently whenever a backing service was unavailable.
