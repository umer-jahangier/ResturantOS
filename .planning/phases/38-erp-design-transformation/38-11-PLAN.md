# 38-11 — The command palette

## Goal

A palette that finds orders, customers, products, tables and people — not one that finds
"Dashboard" when you type "ord".

## Why

Phase 20 §0 calls the command palette *"the primary navigator"* and the thing that *"makes the
two-tier nav survivable — if you can't find it, you type it."* Measured:

- `components/ui/command-palette.tsx` is **87 lines**.
- `⌘K` opens a 384 × 250 dialog. Typing **`ord`** returns **one** result — **"Dashboard"** — under
  a single category, **"Navigation"**. `evidence/shots/command-palette-query-desktop-light.png`.
- The match is a **subsequence**: d-a-s-h-b-**o**-a-**r**-**d**. That is why an order search
  returns a dashboard.
- `aria-modal` is **`null`**.

It searches navigation labels and nothing else. Brief §12 requires orders, customers, products,
menu items, tables, employees, suppliers, pages and settings, with categorised results, keyboard
navigation, recent searches and quick actions.

This matters more than it looks: the sidebar carries 19–23 items depending on route, and a
keyboard user currently spends **22 Tab presses** reaching page content (38-15). The palette is
the escape hatch for both, and it does not work.

## Tasks

1. **Replace subsequence matching with prefix and word-boundary matching.** `ord` must match
   `ORD-20260811-0017` and `Orders`, and must not match `Dashboard`.

2. **Widen the search scope** to the entities the brief names: orders · customers · products ·
   menu items · tables · employees · vendors · pages · settings. Each entity type is a labelled,
   keyboard-navigable category.

3. **Layer discipline.** The palette takes results as props from Layer-3 hooks. **It does not
   fetch** — the ESLint 4-layer boundary covers `components/**` and `app/**`, and a palette that
   calls a repository is a lint failure, correctly.

4. **Permission filtering** through the existing `useNavItemVisible` / `useNavGroupVisibility`
   hooks, so the palette cannot surface a route the user cannot open. The permission matrix is
   frozen by `nav-permission-matrix.test.tsx` and is **not touched**.

5. **Recent searches** — last 5 selections, per user.

6. **Quick actions** — `New order`, `Open till`, `New purchase order` — permission-filtered.

7. **Empty state** — `Nothing matches "{query}".` plus the list of categories searched, so the
   user learns the scope rather than guessing it.

8. **`aria-modal="true"`**, focus trap, `Esc` to close, arrow-key navigation, `Enter` to select.

9. **Debounced query**, with a loading state that does not clear the previous results (§37).

## Zone

The palette is portalled to `document.body`, **outside every zone subtree**. It therefore **stamps
its own zone** from React context, as 34-01 established — a rule written against DOM ancestry
matches nothing here, and would be present in the stylesheet and absent on the screen. Glass
applies only when the stamped zone is `expressive`.

## Verification

| Check | Kind | Passes when |
|---|---|---|
| **Matching** | unit | `ord` matches `Orders` and `ORD-…`; **does not match `Dashboard`**. Asserted as a named case, because that is today's defect |
| Scope | e2e | a real seeded order number, customer name and menu item are each findable |
| Categories | e2e | results are grouped and labelled |
| Permission filtering | unit | a cashier's palette does not surface a finance route; reuses the frozen matrix |
| **No fetching** | unit | lint: the palette imports nothing from Layer 1 or 2 |
| Recents | e2e | last 5 persist across a reload |
| Empty state | unit | names the query and the categories searched; never "No results" |
| Keyboard | e2e | `⌘K` opens, arrows move, `Enter` selects, `Esc` closes, focus returns to the trigger |
| `aria-modal` | e2e | `true` |

### Negative controls — observe each failing

1. Restore subsequence matching → the `ord`/`Dashboard` case must go red. **Run this against
   today's code first and confirm it reproduces the live defect** — if the check passes against
   the current 87-line palette, the check is wrong.
2. Import a repository into the palette → lint must fail.
3. Grant the palette a route the user lacks permission for → permission check red.
4. Replace the empty copy with "No results" → empty-state check red.
5. Remove `aria-modal` → red.
