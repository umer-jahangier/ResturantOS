<objective>
Build the data layer and the pickers, once, so the four screen plans in wave 5 are presentation only.

Wave 2 and 3 added six new API areas: departments, designations, tax configuration, salary components,
component assignment, and the changed employee shape. None of them exist in the frontend yet — no Zod
schema, no adapter, no model, no repository method, no hook. And the pickers those screens need overlap
heavily: the employee form, the attendance screen and the schedule screen all want an employee picker;
the employee form and the settings screen both want a department select.

Building them per screen is how four slightly different department dropdowns appear. Building them here
is also what lets wave 5 run four plans in parallel with no shared files.

Purpose: every wave-5 screen is written against these exports, and the HR sub-navigation must know about
their routes before they exist or the first one to ship is unreachable.
Output: the four API layers for everything wave 2 and 3 added, seven option-source components, and the
section navigation.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-09-A | Information Disclosure | Option lists cached across a branch or tenant switch | high | mitigate | Query keys follow the existing branch/tenant-scoped namespace; the branch switcher already invalidates the cache, and tenant-scoped keys are chosen deliberately rather than by copying |
| T-29-09-B | Tampering | A failed options query rendering as an empty set | medium | mitigate | Pending, failed and empty are three distinct rendered states, each with a test |
| T-29-09-C | Tampering | Decimal precision lost on a tax rate in transit through the UI | high | mitigate | The serialisation choice is read from the API rather than assumed, preserved through all four layers, and asserted by an adapter round-trip test |
| T-29-09-D | Information Disclosure | A navigation tab disclosing a capability the user lacks | low | mitigate | Configuration tabs are conditioned on the view permission rather than shown and then refused |
| T-29-09-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages. If one becomes necessary, halt and require the package-legitimacy audit plus a blocking human checkpoint |
