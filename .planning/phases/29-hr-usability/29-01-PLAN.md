<objective>
Make the server name the field. Today the frontend cannot bind an error to an input because for most
HR rejections the server never says which input is wrong: `EmployeeService` throws
`IllegalStateException("Employee number already exists")`, which the shared catch-all turns into a
`500 INTERNAL_ERROR` with a generic body. `ShiftController` and `LeaveController` take
`@RequestBody` with no `@Valid`, so their DTO constraints never execute at all.

The one part that already works is bean validation: `MethodArgumentNotValidException` is mapped to
`400 VALIDATION_FAILED` with `details: [{field, issue}]`, and the frontend's `ApiError` already parses
that into `fieldErrors`. This plan extends that same envelope to business-rule rejections instead of
inventing a second one, and closes the `@Valid` gap so the envelope is actually reachable.

Purpose: D-29-03 states plainly that field paths are a backend job. Every frontend plan in this phase
binds errors to inputs; none of them can until this lands.
Output: two shared exception types with field paths, HR services throwing them, and a reflection test
that stops a future controller from re-opening the `@Valid` hole.
</objective>

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-01-A | Information Disclosure | Error message content | high | mitigate | Instructions are authored for the form-filler; the JDBC message is not echoed; a test asserts no table/column/constraint vocabulary appears in any body produced by the new handlers |
| T-29-01-B | Information Disclosure | Duplicate-value 409 as an enumeration oracle | medium | accept | The field is scoped to the caller's own tenant by RLS, so the only fact disclosed is that a value the caller may already list is taken; refusing to say so would make the form unusable |
