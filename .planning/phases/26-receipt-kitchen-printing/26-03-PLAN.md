<objective>
Make the receipt real on the server: assemble a `PrintDocument` from persisted order data, record
every issue of it as a durable row, and expose the two endpoints the browser and the print agent
will both use.

This is the plan that turns GA-012 — "no printed receipt anywhere, and the FBR QR has no
destination" — from a missing feature into a wired one. `grep -rn "[Rr]eceipt"
services/pos-service/src/main/java` returns zero hits today; after this plan the settlement path
has a document to hand to a printer.

The `print_jobs` table introduced here is deliberately load-bearing beyond this plan: it is the
reprint history (26-08), the kitchen ticket queue (26-07) and the agent's work list (26-11). One
table, one truth about what was printed.

Purpose: D-26-01's plain tier cannot ship without a server-produced document, and D-26-02's
emulator-based proof needs something deterministic to render.
Output: a migration, an assembler, an issuance service, and two endpoints.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to pos-service | A cashier names an order id and receives a customer-facing financial document |
| pos-service to user_db via Feign | Branch identity and printer configuration cross a service boundary into a printed document |
| pos-service to pos_db | Documents and their issue history are written under forced row-level security |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-03-A | Tampering | Client-supplied money on the receipt | critical | mitigate | The request body carries an order id and nothing else; every printed figure is read from persisted rows and the assembler asserts both money identities before returning |
| T-26-03-B | Information Disclosure | Cross-tenant document read | critical | mitigate | Every repository predicate names the tenant column in addition to the forced policy; the negative case is asserted with the tenant context switched |
| T-26-03-C | Repudiation | An untracked reprint | high | mitigate | Every issue writes a row with a sequence; the reprint flag and the original timestamp travel on the document |
| T-26-03-D | Tampering | A reprint that silently differs from the original | high | mitigate | The reprint re-serves stored bytes and never re-assembles; asserted by byte identity and by an assembler call-count assertion |
| T-26-03-E | Denial of Service | A settings lookup blocking a settlement | high | mitigate | A user-service failure degrades the document rather than failing it, and the degradation is recorded on the document |
| T-26-03-F | Elevation of Privilege | A weaker authority for printing than for reading the order | medium | mitigate | Both endpoints reuse the order-view permission expression; `ControllerAuthorizationClosureTest` fails the build on an ungated method |
| T-26-03-G | Tampering | Duplicate sequence allocation under concurrency | medium | mitigate | Pessimistic lock plus a unique index on (tenant, order, type, sequence); the concurrent case is a test, not an assumption |
| T-26-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan adds no package to any manifest. If one becomes necessary, halt and require the package-legitimacy audit plus a blocking human checkpoint |
</threat_model>
