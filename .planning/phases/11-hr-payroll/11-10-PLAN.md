<objective>
Build the device registry (HR-07) and the JWT-exempt, device-authenticated gateway path class + DeviceAuthResolver that the ADMS/USB ingest (11-11) will sit behind. This is the highest-risk security surface — isolate and get the auth boundary right BEFORE any punch parsing exists.

Purpose: Punches arrive with no user JWT. The gateway must skip JWT for /iclock and /internal/attendance/ingest yet keep FEATURE_HR gating and rate limiting; hr-service (not the gateway) is the real auth boundary via the device token, and tenant/branch MUST come from the registry.
Output: attendance_devices CRUD + gateway device-auth path + DeviceAuthResolver, all tested.

CRITICAL pitfalls (RESEARCH):
- Do NOT reuse X-Internal-Service / InternalServiceFilter for /internal/attendance/ingest — StripInternalHeaderFilter strips that header from all external traffic. Use the device-token scheme.
- Set TenantContext MANUALLY from the registry (no X-Tenant-Id header exists on this path); mirror what TenantAwareMessageProcessor does for AMQP.
- Keep /iclock OUT of FeatureFlagGlobalFilter's public-prefix list so FEATURE_HR still gates it.
</objective>
