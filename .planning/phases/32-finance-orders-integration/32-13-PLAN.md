<objective>
The tab the user asked for by name: *"a complete guide tab in Financial system which will explain how
this module is working, what each tab/module is and how it functions."*

Ten finance tabs now exist — Takings, Transactions, Accounts, Journal Entries, General Ledger, Periods,
Expenses, AP Aging, House Accounts, AR Aging — and nothing in the product explains any of them. An
owner meets a chart of accounts with no idea what it is for, and meets a 409 when settling a cash sale
with no idea why card worked and cash did not.

D-32-03 is explicit about the shape: plain language, four things per tab, and the specific rules that
will otherwise generate support tickets. And it is explicit about the constraint that makes this hard —
the guide must be verified, not merely written, because a guide that lies is worse than no guide.

Plan 32-02 built the mechanism for that: a registry where each claim names the test that proves it, and
a two-way gate that fails when a claim has no live assertion or an assertion has no claim. This plan
writes the content, registers every claim the phase's earlier plans made true, places the markers in
those plans' tests, and renders the guide from the registry so a sentence with no proof has no path to
the screen.

Purpose: the module is unexplained, and an explanation nobody checks decays into a liability.
Output: a guide tab covering every finance tab, with every behavioural claim under test.
</objective>
