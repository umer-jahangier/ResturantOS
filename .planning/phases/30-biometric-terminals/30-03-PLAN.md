<objective>
Give a terminal the properties a person managing terminals needs it to have.

Today `attendance_devices` knows a serial, a model, a connection mode, an encrypted token, a
last-seen timestamp and an active flag. That is enough to authenticate a device and nothing else.
D-30-01 asks for a device you can name, assign, disable and rotate; D-30-02 asks for silence to be
measurable; the user's own sentence asks for terminals that auto-sync with the app, which is a set of
handshake values currently hard-coded as a string literal in a controller method. None of those
properties have anywhere to live.

This plan adds the places. It adds no behaviour: the columns it creates are read by 30-05, 30-07,
30-08, 30-09 and 30-10, and every one of those plans is where the corresponding behaviour is proven.
A column with no reader is exactly the shape of the last-seen timestamp this phase exists partly to
fix — so this plan's summary must name the plan that reads each column it adds.

Purpose: five later plans have nowhere to put their state until this lands.
Output: one changeset, an updated entity, health-oriented repository queries, and a test that the
mappings and the schema agree.
</objective>

    silent-since timestamp. The silent-since column exists so that 30-09 can alert on the transition
    into silence rather than on the state of being silent — an alert that re-fires every sweep is an
    alert that gets muted, and a muted alert is how a terminal stops talking for three days unnoticed.

    *Clock discipline.* A maximum acceptable skew in seconds, defaulted to a small number of minutes.
    Skew itself is never stored: it is the difference between the two timestamps already on every
    punch row, computed where it is read.

    realtime push as a boolean, poll delay, error delay, transfer interval, the transfer-times window

    emits today, so migrating changes no device's behaviour by a single character. Comment the

    next reader does not treat it as a free-text field.
