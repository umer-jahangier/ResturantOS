## Accomplishments
- `RecipeDtos.CoverageState` (COVERED/SCHEDULED/NO_RECIPE) and `MenuItemCoverageDto` added; `CoverageResponse` extended with `covered`/`scheduled`/`noRecipe` counts and an authoritative `items[]` list, keeping `missing[]` additive (now NO_RECIPE-only) so the pre-existing frontend and MSW mock keep compiling until 08.2-12.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Truncated seeded/compared Instants to microsecond precision in RecipeCoverageIT**
- **Found during:** Task 2 (`scheduledFromReportsTheEarliestFutureVersion`)
- **Issue:** `Instant.now().plus(...)` carries nanosecond precision; Postgres `timestamptz` columns store microsecond precision, so the round-tripped `scheduledFrom` failed `isEqualTo` by ~500ns (`...248065500Z` vs `...248066Z`).
- **Fix:** Added `.truncatedTo(ChronoUnit.MICROS)` to the seeded `Instant` values in `futureDatedRecipeIsScheduledNotMissing` and `scheduledFromReportsTheEarliestFutureVersion` so the pre-persistence value matches the post-round-trip value exactly.
- **Files modified:** `services/inventory-service/src/test/java/io/restaurantos/inventory/RecipeCoverageIT.java`
- **Verification:** `mvn -Dtest=RecipeCoverageIT test` — all 8 tests pass.
- **Committed in:** `1f12f12` (Task 2 commit)
