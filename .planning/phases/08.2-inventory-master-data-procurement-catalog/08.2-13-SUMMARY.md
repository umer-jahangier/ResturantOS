## Decisions Made

- `createPurchaseOrderLineInputSchema.vendorItemId` is `z.string().uuid(...).or(z.literal(""))` plus a whole-object `.refine()` checking non-emptiness, rather than a bare `.uuid()`. This lets a freshly-appended, not-yet-picked form row default to `""` without a validation error firing until submit (matching the UI-SPEC's "surface the error only on submit" requirement), while still producing the friendly "Select a catalog item before adding this line" message instead of a generic UUID-format error.
- `priceOverridden`/`vendorSku`/`packDescription`/`vendorItemId` on `apiPoLineSchema` are all `.nullable().optional()` per the plan's literal instruction, even though the backend's `priceOverridden` is a primitive `boolean` that is never actually `null` — harmless (a concrete boolean still validates against a nullable-optional boolean schema) and keeps the schema forgiving during the Wave 4/5 transition.
- Two endpoints (single-invoice detail, the vendor price-changes report) have no dedicated factory in `queryKeys.purchasing` (a gap 08.2-05 didn't enumerate) — built as manual `["purchasing", branchId, ...]` tuples mirroring the registry's own shape, the same class of gap 08.2-12-SUMMARY documented and filled the same way for inventory's `stockLevels`/`search`.
- `useVendorCategories`/`useReplaceVendorCategories` append `vendorId` as an extra tuple element onto `queryKeys.purchasing.vendorCategories(branchId)` (which only takes `branchId`), mirroring `use-inventory.ts`'s `useStockLevels` search-append pattern.
