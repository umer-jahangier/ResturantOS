  <behavior>
    - Resetting a target sets a newly generated temporary password, sets the forced-change flag, clears the failed-login counter and the lockout timestamp, appends the previous hash to history, and revokes the target's refresh sessions.
    - The operation returns the temporary password exactly once.
    - The target's next login is met with the forced-change refusal, and the temporary password redeems it.
    - Resetting a target in a different tenant than the one asserted returns not-found.
    - The emitted audit event names the acting administrator id and the target user id as distinct fields, and carries no password material.
    - Resetting a target who holds the highest tenant role is refused when the caller is not itself entitled to that tier.

  <action>
    Run GitNexus impact analysis on PasswordPolicyService before editing.

    Create AdminPasswordResetService with a single reset routine taking the tenant id, the target user
    id, the acting administrator id, an actor tier discriminator and a reason. Set the tenant GUC as the
    first statement of the transaction, before any row-level-security-scoped read, so the GUC and the read
    share one connection.

    Compose the routine entirely from the shared policy service — history append, session revocation,
    lockout clearing — plus the existing temporary-password generator and the forced-change flag. Do not
    reimplement any of them. Two reset implementations that diverge is the failure this phase keeps
    finding, and after plan 13-09 there is exactly one correct way to do each of these steps.

    Implement the privilege check by reading the target's active roles: a caller at the tenant tier may
    not reset a target holding the highest tenant role. A caller at the platform tier may. Encode that as
    a single method with the tier as an argument rather than duplicating the guard in two callers.

    tier and the reason. Model it as a typed payload record in the shared payload package. The acting
    administrator and the target must be separate fields with unambiguous names — the audit found the
    impersonation path passes the target as the actor, and this is the same shape of mistake a hurried
    implementation would repeat. No password material may appear in the payload.

    Create AdminPasswordResetInternalController under the internal auth prefix. Both public tiers call it.

    Write AdminPasswordResetIT covering the six behaviours, asserting the event payload's actor and target
    fields hold different values in a case where the two are genuinely different people.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant admin to gateway | An authenticated tenant user takes over another account's credential |
| SuperAdmin to gateway | A platform operator takes over any tenant account's credential |
| auth-service to the outbox | An audit record of a credential takeover becomes durable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-13-A | Elevation of Privilege | Admin reset as an account-takeover primitive | critical | mitigate | Gated by tier-appropriate authority; tenant scope from the verified JWT; a tenant-tier caller cannot reset the highest tenant role; all refusals asserted live |
| T-13-13-B | Information Disclosure | Cross-tenant reset | critical | mitigate | Tenant GUC set first in the transaction; cross-tenant target returns not-found; proven against a second genuinely provisioned tenant |
| T-13-13-C | Repudiation | Audit naming the wrong actor | high | mitigate | Actor and target are distinct typed fields, asserted distinct in a test and in the live outbox read; the actor comes from the verified principal only |
| T-13-13-D | Information Disclosure | Temporary password handling | critical | mitigate | Returned once to the authorised administrator; never logged, persisted plaintext or evented; forced-change flag bounds its life |
| T-13-13-E | Denial of Service | Reset used to lock a rival out | medium | mitigate | Every reset is audited with actor, target and reason; the reason field is required |
| T-13-13-F | Elevation of Privilege | Platform tier resetting any tenant user | high | accept | A deliberate support capability, accepted; compensated by the audit event, the SuperAdmin authority gate, the rate-limited platform route and the short non-refreshable platform token |
| T-13-13-G | Spoofing | Acting-administrator id from the request body | high | mitigate | Both tiers read the actor from the verified principal; a body field is not accepted, asserted by test |
| T-13-13-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages. If one becomes necessary, halt and require the package-legitimacy audit plus a blocking human checkpoint |
</threat_model>
