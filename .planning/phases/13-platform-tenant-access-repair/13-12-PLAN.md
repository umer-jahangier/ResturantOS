<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant admin to gateway | An authenticated tenant user requests privileged changes to other accounts |
| gateway to user-service | The tenant identity is asserted by a gateway-injected header |
| user-service to auth-service internal | The administrative intent crosses on a shared secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-12-A | Spoofing | Tenant scope selection | critical | mitigate | Scope comes only from the gateway-injected header derived from the verified JWT; the strip filter prevents client supply; a tenant id in the body is asserted to have no effect |
| T-13-12-B | Information Disclosure | Cross-tenant user access | critical | mitigate | Row-level security in auth-service plus not-found responses; proven against two genuinely provisioned tenants rather than a fabricated id |
| T-13-12-C | Elevation of Privilege | A tenant admin minting the highest tenant role | high | mitigate | An explicit role ceiling checked from the caller's authorities in the service layer, covering both create and assignment paths |
| T-13-12-D | Elevation of Privilege | Missing authorization on new endpoints | critical | mitigate | Every new method carries the same authority gate as the three pre-existing ones; a 403 and a 401 case are asserted live |
| T-13-12-E | Information Disclosure | Temporary password in the create response | high | mitigate | Returned once over TLS to an authorised admin, never logged or persisted plaintext; the forced-change flag bounds its life |
| T-13-12-F | Tampering | Upstream 400 collapsing into a 500 | medium | mitigate | The Feign error path is decoded explicitly so an unknown role code surfaces as 400, asserted by test and live |
| T-13-12-G | Repudiation | Administrative changes without attribution | medium | mitigate | The gateway propagates the acting user id, and auth-service's auditing columns record it; the impersonation header is propagated where present |
