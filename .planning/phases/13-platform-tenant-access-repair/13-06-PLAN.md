<objective>
Build the auth-service half of blocker B2 (D-04, D-05): the tenant row that login resolves by slug, and
the OWNER branch-role assignment without which `PermissionResolver` throws "User has no active branch
assignments" at the first login attempt. Also add role-code validation (D-13), because an unvalidated
role code is what turns a successful assignment into a permissionless login.

Plan 13-10 consumes these from the platform-admin saga. Splitting the work by service keeps the two
plans in different files and therefore in different waves without serialising on a shared file.

Purpose: the saga cannot be repaired until the operations it needs to call exist.
Output: an auth-tenant provisioning service, an extended provision-admin operation, and role validation.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| platform-admin-service to auth-service internal | A trusted service asserts a tenant and an admin should exist |
| auth-service to auth_db | Tenant, user and role-assignment rows are created |
| provisioning response to caller | A one-time temporary credential crosses back |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-06-A | Elevation of Privilege | Internal provisioning endpoints | critical | mitigate | Gated by the constant-time internal-secret filter; never routed publicly; a 403 case is asserted |
| T-13-06-B | Elevation of Privilege | Unvalidated role code | high | mitigate | Every caller-supplied role code is resolved against the roles table and rejected when unknown, in both the provisioning and the assignment paths |
| T-13-06-C | Information Disclosure | Temporary password handling | critical | mitigate | Returned once in the response body, never logged, never persisted plaintext, never placed in an event payload; asserted by grepping the outbox payload for the returned value in plan 13-10's live script |
| T-13-06-D | Denial of Service | A provisioned admin with no branch assignment | critical | mitigate | Both writes share one transaction; a rollback assertion proves partial success is impossible |
| T-13-06-E | Tampering | Slug collision across tenants | high | mitigate | Explicit findBySlug check producing a mappable conflict rather than a driver integrity error the saga would mis-handle |
