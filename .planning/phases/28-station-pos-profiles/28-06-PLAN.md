<objective>
Give the station CRUD a user. It has none.

The backend has had complete station CRUD since phase 3 — list, create, update, deactivate, all guarded,
all covered by nine integration tests. A grep for the word station across
`frontend/lib/repositories/pos.repository.ts` returns zero matches. The only station-aware frontend code
reads the kitchen-service projection for the board. So for the entire life of this product, creating a
station has required curl. The audit says the same thing in fewer words: the backend CRUD exists and is
completely unused by the frontend.

That is precisely what D-28-05 refuses: *"Nothing should be needed to seed directly via developers or
support team."* A bar station that only a developer can create is not a bar station a restaurant owner
has.

This plan also owns the shared navigation file for the whole phase. Both the Stations entry and the
Terminals entry are added here, in one edit, so that plan 28-09 never has to touch a file another agent
might be editing in the same wave. Phase 19b hit that exact collision on this exact file.

Purpose: the first two steps of the definition of done — creating a BAR station — become possible in a
browser.
Output: the four frontend layers for stations, a Stations screen, and both nav entries.
</objective>
