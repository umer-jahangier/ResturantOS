<objective>
Turn the token layers into three primitives other phases compose, and foreclose the shortcut that
makes a "3D effect" a lie.

The named failure mode is a four-hundred-kilobyte library rendering two shadows. It is not a
hypothetical: a scene-graph runtime is genuinely the fastest route to something that looks
three-dimensional, and it is the wrong one for a product whose most important screens run on a
cheap Android tablet over restaurant wifi. D-27-06 already ruled it out. This plan makes the ruling
enforceable by asserting the dependency manifest is unchanged and by naming, in the test, the
packages that satisfy the temptation.

The second thing this plan gets right or gets wrong for the whole phase is the tilt implementation.
A tilt that reads its element's geometry on every pointer move forces a synchronous layout per
frame. It will look perfect in a component test and stutter on a dashboard with twelve tiles, and
the stutter will be blamed on the glass. The rectangle is measured once on entry and only transform
values are written afterwards.

Purpose: 27-06 and 27-07 build screens out of exactly these three pieces. Every surface decision
made here is made once instead of per screen.
Output: a glass panel, a depth variant on the existing card, a reveal wrapper, a tilt hook, and a
dependency gate.
</objective>

    - A revealed element's resting style is its finished style: rendered with the animation suppressed, it is at full opacity with an identity transform.
    - A sequence of revealed children receives increasing delays derived from the stagger token and an index, with no per-child hand-written delay.
    - Under a reduced-motion preference the reveal wrapper applies no animation class at all.
    - The tilt hook engages only on a fine pointer, only without a reduced-motion preference, and only in the expressive zone; each exclusion is asserted independently.
    - The tilt hook reads element geometry exactly once per pointer entry, regardless of how many moves follow.
    - The tilt hook writes only transform-family values, and a test asserts the set of properties it touches.
    - Pointer leave returns the element to identity, and unmounting mid-gesture removes every listener.
    - Changing the reduced-motion preference while the pointer is over the element disengages the tilt without a reload.
  </behavior>
  <action>
    Build the reveal wrapper around the resting-state contract, not around an animation. It applies a
    zone-scoped entrance class and, for a sequence, an index-derived delay expressed through the
    stagger token. Its default is to do nothing: no zone, no motion preference, or no explicit opt-in
    yields a plain element. The test that matters is the one rendering it with the animation
    suppressed and asserting the content is visible, because that is the reduced-motion user's view
    and it is the view nobody looks at.

    Build the tilt hook as a pointer-position-to-transform mapping with three specific properties.

    Measure once. Take the element's rectangle on pointer entry and cache it for the gesture. Do not
    read it per move. If the layout can change mid-gesture, invalidate on scroll or resize rather than
    re-reading every frame — invalidation is cheap and per-frame measurement is not.

    Write once per frame. Coalesce moves through an animation frame so a high-rate pointer cannot
    schedule more work than the compositor consumes, and cancel any pending frame on leave and on
    unmount.

    Write transforms only, through custom properties the stylesheet consumes, so the component never
    sets an inline transform string and the stylesheet keeps ownership of the rotation limits. Keep
    the rotation small; D-27-06 asks for depth, and a tile that swings is a toy.

    Every exclusion is checked in the hook itself and re-checked when it can change: a coarse pointer,
    a reduced-motion preference, and a zone that is not expressive. The coarse-pointer exclusion is
    what keeps this off a restaurant tablet even if a future screen composes it wrongly.

    Write all eight behaviours as tests before implementing. The measure-once behaviour is asserted by
    counting geometry reads across many synthetic moves, not by inspecting the code.
  </action>
