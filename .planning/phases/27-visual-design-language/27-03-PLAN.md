<objective>
Give the product a motion vocabulary, and build the gate that proves the motion is both present and
escapable.

D-27-03 is usually satisfied on paper by the global reduced-motion block that already exists in
this stylesheet, which collapses every animation to a hundredth of a millisecond. That is not what
D-27-03 asks for. It asks for decorative motion to be *absent*, and it is only safe to make it
absent if every animated element's resting style is already its finished style. Author it the other
way round — hide the element and let a keyframe reveal it — and the reduced-motion path renders a
blank screen. So the contract this plan establishes is structural, and the gate checks the
structural property directly: under reduced motion, the animated elements must be *visible and
still*, not merely still.

The gate runs in both directions, and the second direction is the more interesting one. A motion
system that does nothing at all passes every stillness test ever written. So the same spec asserts
that without a reduced-motion preference the screen demonstrably changes between first paint and
half a second later. Present and escapable, both asserted.

This plan also retires a motion defect that ships today: a 350ms fade-and-slide wraps every
navigation in the tenant shell, which means the KDS board and the POS terminal play an entrance
animation on every route change. D-27-02 forbids exactly that on those two screens.

Purpose: 27-04 through 27-07 all animate. They need a vocabulary and a proven escape hatch first.
Output: motion tokens, a reduced-motion reader for imperative code, the retirement of the global
page transition, and a two-direction gate.
</objective>
