<objective>
Rebuild the screen the complaint was about.

The Employees page today is nine `<Input placeholder="...">` elements in a two-column grid, held in a
single `useState` object, with no labels at all — the placeholder is the label, which disappears the
moment anyone types. Designation is free text. Department is not on the form at all, despite existing in
the API and the database. The salary is a raw number input labelled with a currency symbol that differs
from the rest of the product. There is no validation of any kind before submit, and the failure handler is
one line: a fixed failure toast, so a duplicate employee number, an invalid date and a server outage are
indistinguishable to the person who has just typed nine fields. There is no edit path — only create and
deactivate — even though the API has had an update endpoint since phase 11.

Purpose: definition-of-done items 1, 2 and 3 are demonstrated here more directly than anywhere else in the
phase.
Output: one dialog serving create and edit, built on the standard, with every closed set a select.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-10-A | Tampering | Masked CNIC or bank account submitted back as the real value | critical | mitigate | Masked values render read-only with an explicit replace affordance; an unreplaced field is omitted from the payload entirely, asserted by a behaviour test |
| T-29-10-B | Information Disclosure | Unmasked PII reaching a log, a query cache key or an error message | high | mitigate | Raw values live only in form state; nothing is put in a query key; server messages are bound to fields and are not echoed with their submitted values |
| T-29-10-C | Elevation of Privilege | Edit action visible or effective without the manage permission | high | mitigate | The action is inside the existing `PermissionGuard`, and hr-service enforces the permission and branch isolation independently |
| T-29-10-D | Tampering | Salary rounding drift between rupees and paisa | high | mitigate | Conversion happens in exactly one transform between the form and the request schema; the money display rule from GA-078 is preserved |
| T-29-10-E | Information Disclosure | A filtered-empty roster read as an empty tenant | low | mitigate | Three distinct empty states with distinct copy |
| T-29-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages. If one becomes necessary, halt and require the package-legitimacy audit plus a blocking human checkpoint |
