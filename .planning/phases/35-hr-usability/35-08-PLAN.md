<objective>
Make salary components real, and make payroll consume them.

`PayrollRunService.calculate` today contains `long gross = basic; // allowances/overtime placeholder 0
for now` and writes `slip.setAllowancesJson(new HashMap<>())`. There is no component table, no assignment,
and no way for a restaurant to pay anyone a house-rent allowance or deduct a loan instalment. D-35-05
names salary components among the things that must be CRUD from the UI, and shipping a catalogue that
payroll ignores would be this project's own failure mode reproduced deliberately — structurally present,
behaviourally absent.

This plan also lands the fiscal-year adoption that plan 29-06 deliberately left: `calculate` still
computes the fiscal year inline, and this is the plan that owns the file.

The ledger identity `net + tax + eobi + advances == gross - lateArrival` is asserted by finance's posting
path, and the existing negative-net refusal exists because clamping would break it. Folding components in
changes both sides of that identity, so it is restated and re-asserted here rather than assumed to
survive.

Purpose: definition-of-done items 4 and 5 — an owner configures salary components in the UI, and payroll
runs end to end.
Output: a component catalogue, per-employee assignment, a calculator with no floating point, and a payroll
engine that uses them.
</objective>
