<objective>
Give the tenant-managed lists a place to be managed.

Departments and designations have had no screen at all — plan 29-05 built the API and this is where an
owner reaches it. Leave types have an API and appear on the Attendance screen only as a button labelled
for seeding defaults. Shift definitions are created from a strip of inputs at the top of the Schedule
page, where the days a shift runs are typed as the string `1,2,3,4,5` into a text box, parsed with
`split(",").map(Number).filter(n => !Number.isNaN(n))` — which silently discards anything it cannot
parse, so a typo produces a shift that runs on fewer days than intended and says nothing.

Every one of these lists is empty on day one, deliberately: plan 29-02 seeds nothing because the user
ruled out anything needing a developer. That makes the empty state the first thing every owner sees here,
and it has to be an instruction rather than a blank.

Purpose: definition-of-done item 4, for four of the six things it names.
Output: a settings area with four list screens, four dialogs on the standard, and a day-of-week control
that cannot silently drop a day.
</objective>
