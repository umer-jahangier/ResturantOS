<objective>
The centrepiece, rendered. "There was no system to see all the orders transactions in the app" — this
is that system.

A Transactions tab in Finance listing every money event of a trading day: each tender applied, each
refund, each void. Filter by date range, branch, terminal, cashier, tender method and status. Expand a
row and see the journal entries that money produced, each linking to the entry, and the entry naming
this order back. That round trip is D-37-01's actual requirement and the reason the tab exists.

Two constraints from this project's own history govern the rendering. A failed request must never look
like an empty day — phase 14b found eleven screens doing exactly that, and on a takings screen it means
"you sold nothing today", which an owner would act on. And an unresolved ledger link must be
distinguishable from an order that genuinely produced no entries; those are opposite facts and a shared
dash makes them look identical.

This is the first of three finance tabs this phase adds, so it owns the tab bar. Plans 32-12 and 32-13
each add their own tab in a later wave rather than racing this file.

Purpose: an owner cannot see the day's transactions at all today.
Output: a filtered register with a working, tested round trip to the ledger and back.
</objective>
