<objective>
Prove the phase, once, against the live stack, in the way 22b proved things: by driving real
transactions and reading what actually persisted.

Fourteen plans produced twelve verification scripts and dozens of tests. Every one of them is scoped to
its own plan. This plan runs the phase's six Definition-of-Done items as one sequence against the
running product and records the evidence, because a phase is done when someone can point at a single
artefact and see it.

It also builds the check 22b said was missing. `scripts/build-freshness.ps1` compares timestamps, which
cannot detect the failure that actually occurred: a JVM holding an open descriptor on a deleted jar
whose modification time is older than the replacement's. The check that works is inode identity, and
22b wrote it in four lines. Every assertion in this run is worthless without it — the discount fix was
present in source, present in the artifact, covered by tests, and not running, for four and a half
days, on a live system taking discounted orders.

Purpose: a phase is done when its Definition of Done is demonstrated, not when its plans are.
Output: one acceptance run, one evidence file, and a freshness gate the whole repository can use.
</objective>

    Gate the whole run on the freshness check from task 1. If any service the run touches is stale or not
    running, abort before asserting anything and say so. A green acceptance run against a stale jar is
    the single most expensive kind of wrong output this repository can produce.

    Drive real money through the product, through the gateway, as a real persona — not by inserting
    rows. Open a till, take orders including a discounted one and a comped one, settle across cash and
    card, refund one, void one, close the till with a deliberate shortfall. Then assert:

      1. Takings: the finance landing screen's figures for that business date, tender split included,
         with the till variance equal to the shortfall created.
      2. Traceability: a transaction opens to its order and to its journal entries, and one of those
         entries names the order back — both directions asserted, since one direction is not
         traceability.
      3. Cost and margin: the reports return real figures for that date, and the independent
         recomputation from plan 32-10 exits zero.
      4. Dates: the ledger and the report name the same day for every order, including one closed inside
         the window where the two old formulas disagreed.
      5. The guide: the claim gate exits zero, and the coverage test passes for every tab currently in
         the tab bar.
      6. The queue: the ownership check exits zero and the retired queue is absent from the broker.

    Every reconciliation compares two independently sourced numbers. Read `finance_db` as `finance_user`,
    `pos_db` as `pos_user`, and each other database as its own role, with the tenant GUC set on the same
    connection as the read. A superuser read bypasses FORCE RLS and would assert something the services
    themselves cannot see, which is a green light for a policy that does not work.

    Count and report three outcomes — passed, failed, skipped — separately. A skip is not a pass, and a
    run that quietly skips an assertion because a precondition was absent is how a Definition of Done
