<objective>
Make the ledger answer "where did this number come from?".

The data is already there and has been since phase 9: `journal_entries` carries `source_type` and
`source_id`, `posted_source_events` indexes every source to the entry it produced, and
`JournalEntryDto` already ships both fields to the client. What does not exist is a way to query by
source, a way to turn a source id into something an owner recognises, and any assurance that asking
an order what it produced returns all of it rather than one entry.

That last point matters more than it looks. A single closed order can produce three entries — revenue
on close, cost of sales when inventory depletes, and a refund later — posted by three different
consumers at three different times. An answer that returns only the revenue entry is not traceability;
it is a plausible partial answer, which is worse, because it looks complete.

This is the ledger half of D-37-01. Plan 32-08 builds the transaction half on top of it, and plan
32-11 renders both.

Purpose: a finance screen that cannot answer where a number came from is not finished.
Output: a by-source query, a resolved human-readable reference, and an honest unresolved state.
</objective>
