<objective>
Make a refused device look refused.

`DeviceAuthException` carries an unauthorized status annotation that has never once run: the shared
advice ends in a catch-all for `Exception`, `ExceptionHandlerExceptionResolver` picks the first
advice bean that can handle the exception rather than the most specific signature across beans, and
so every device-authentication failure in this product's history has been answered
`500 INTERNAL_ERROR`. Verified live through the real gateway on 2026-08-11 against the running stack.

This is the same defect, in the same service, that `TotpRequiredResponseTest` was written to pin for
the payroll step-up gate — and its header comment says so in those words. The fix is the one that
worked there.

Three consequences follow, and the second and third are the ones that matter. A device polls every
three to eight seconds, so one unknown or spoofed serial writes an unhandled-exception stack trace at
that cadence: tens of thousands of ERROR lines a day, a disk-fill vector, and a log in which a real
fault cannot be found. And the gateway's circuit breaker on these two routes trips on 503 only —
correctly, because until now a 500 on this path was overwhelmingly an authentication refusal rather
than a fault, so tripping on it would have taken every branch's terminals offline the first time
somebody typed a serial wrong.

Purpose: nothing else on this path can be observed while its normal refusal is indistinguishable from
its abnormal failure.
Output: a handler, a bounded failure record, a gateway route correction, and three tests.
</objective>

    - Subsequent failures for the same serial inside that window are counted, not logged.
    - When the window closes, a single summary line reports the serial, the cause and the suppressed count — so a sustained attack is louder than a single typo rather than quieter.
