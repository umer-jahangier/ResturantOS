<objective>
Stop the device path losing data to a header and to a return type.

Two mechanisms in the current adapter can make an employee's punch cease to exist with a success
response and no log line. The first is the Content-Type: when a POST arrives declaring form encoding,
the servlet container consumes the body into request parameters, the body binding sees an empty
stream and binds null, and the guard skips the loop. Verified: 200, the success acknowledgement,
zero rows, nothing logged. The documented happy path uses plain text so this does not bite a
by-the-book firmware — but it is a silent-data-loss branch selected by a header the device chooses,
and firmware varies.

The second is the parser's return type. An optional that comes back empty is indistinguishable from
a line that was never sent. Three inputs take that branch today: a line of fewer than four fields
where the reference implementation accepts two, a Unix-epoch timestamp which the reference parser
accepts and this one does not, and anything else the single accepted pattern rejects. Each is a
punch, and a dropped punch is an unpaid hour.

This plan makes both losses impossible in principle: the bytes always reach the parser, and the
parser always returns something. What is *done* with a rejection — retaining and surfacing it, per
D-25-03 — is 30-06, which owns the quarantine. This plan's job is to stop manufacturing silence.

Purpose: D-25-03 cannot be satisfied by a queue if the thing that would populate the queue returns
nothing.
Output: a controller that reads bytes, a parser that reports outcomes, and the device's own timezone
in use.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-05-A | Tampering | Silent data loss via Content-Type | critical | mitigate | The body is read from the request stream and parameter consumption is prevented on the device paths only; the identical body under three content types is asserted to write identical rows |
| T-30-05-B | Tampering | Silent data loss via an absent return value | critical | mitigate | The parser returns a named outcome for every input and has no absent path; asserted by covering every rejection branch |
| T-30-05-C | Tampering | An epoch timestamp shifted by a timezone | high | mitigate | The zone applies only to the device-local pattern; a test asserts an epoch yields exactly that instant |
| T-30-05-D | Denial of Service | An unbounded body from a public path | high | mitigate | Retain the gateway's per-device rate limit, and cap the read at a maximum body size with the cap stated in the handler; an oversized body is rejected rather than buffered |
