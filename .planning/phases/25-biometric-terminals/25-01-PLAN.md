<objective>
Establish, by assertion rather than by assumption, what the ADMS/iClock integration actually does
today.

30-CONTEXT says the protocol work is "largely done and the gap is management, sync and visibility."
That is substantially true and materially incomplete, and this plan exists to settle which parts are
which before eleven other plans are built on top of the claim. This repository has shipped a table
picker writing to a catalogue nothing could populate, sixteen OPA rules enforcing nothing, and an
audit log at zero rows for four days — every one of them looked wired.

A pre-planning probe against the running stack on 2026-08-11 already found one such item live:

    GET http://localhost:8080/iclock/cdata?SN=<unknown>&options=all&pushver=2.4.0
    -> HTTP 500 {"error":{"code":"INTERNAL_ERROR", ...}}

That is the exact request a stock ZKTeco terminal sends on boot, through the real gateway, and
`DeviceAuthException` carries `@ResponseStatus(UNAUTHORIZED)` that never runs. Treat that as one
worked example of the method, not as the finding — verify every row below the same way.

Purpose: nothing later in this phase can be trusted if the baseline is wrong, and the existing
`AdmsIngestIT` cannot see the wire at all.
Output: two integration test classes that go over real HTTP, and one inventory document.
</objective>
